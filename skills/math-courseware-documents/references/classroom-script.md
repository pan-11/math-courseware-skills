# 教师课堂逐字稿

按[四类文档基准](teaching-pack-profile.md)写完整师生课堂预案，默认约5000—6500字符。页面模块的“每页干净逐字稿”指屏幕可见文字，本文件则是教师口语、学生预设与现场组织，两者分开。

## 默认结构顺序

一、基本信息：紧凑表格写课题、课型、课时、对象及真实课件特色。

二、课堂逐字稿：按实际教学环节展开，连续几页可归入一个环节，标页码范围和建议时间。使用“课件：”“师：”“生（预设）：”“AI视频：”“板书：”“学生活动：”等必要标签。先独立观察/操作，再交流；核心问题包含可能回答、必要的错误或不完整回答、教师追问及反馈。备用追问不与主线全部叠加计时，不虚构课堂已经发生。

三、板书设计建议：与教学设计及课堂板书提示一致。

四、备注：只留视频使用、核心难点或弹性安排等少量实用提示。

## 写作

按页序核对最新有效课件的全部教学内容，正文按环节组织，补足观察、提问、组织操作、倾听、追问、讲解和自然转场。内容应像教师能直接使用的课堂语言；不得以每页两三句教师提示代替完整逐字稿，不机械按每页字数/秒数填充。

关键概念说明准确，活动中的学生思考留有空间；核心探究必须有具体学生预设及与之对应的回应，不只写“学生回答”“教师总结”。学生预设不得假称真实课堂记录。视频节点写观察任务、已确认内容、关键对白、片后教师接续与用途；未知部分不编造。

不新增页面、不重排课件、不改已确认题目、数据或结论。外部资料只补理解，实际需要检索时使用可靠来源，不把引用或工程字段塞进每页正文。

## 源稿与旧JSON

默认使用完整MD/JSON源稿生成上述四部分的可编辑DOCX。下面是旧导出器的逐页接口，仅在用户明确要求逐页版且版式适合时使用；不能用它取消基本信息、按环节组织的师生对话、板书或备注。

`_state/documents/classroom-script.json`：title、source_versions、page_order、content。
content按展示顺序逐页包含`{page_id,title,paragraphs:[完整口播段落]}`，一次覆盖全部页面。
整课source_versions记录pages/story/math/assets以及各确认页图实际哈希，可补真实教材来源；page_order对应当前稳定ID顺序。独立逐字稿只登记本次实际输入来源；有课件时保留真实页序，没有课件时按明确用途写段落稿，不伪造页面或全套课程记录。

导出器不撰写课堂内容，Codex先完成全文再生成文件；不要将旧接口可导出等同于新文稿合格。

## 排版

A4竖版，左右约23mm、上下约22mm，正文11—12pt、行距约1.35—1.5。紧凑题头后进入基本信息和课堂环节，不设独立封面；环节标题与后文绑定，师生标签便于扫描，不显示内部ID、JSON或执行状态。需要讲者身份且用户已给时可在紧凑题头自然呈现，不能编造身份。

DOCX结构化标题与正文；PDF使用真实中文字体并保留可选文字，同源内容输出。检查首、中、末页和跨页位置，不能只看生成成功。普通文案质量问题直接修订一版，不加最终审批门槛。
