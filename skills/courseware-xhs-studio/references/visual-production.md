# 图文制作

## 默认封面：故事海报

图文篇与视频篇共用鹿鸣已确认的方向：参照《认识厘米》和《一亿有多大》的故事海报效果，**大课名、满版3D故事画面、人物突出、每篇构图有变化**。这是默认制作偏好；用户当次指定其他样式，或本课已有明确的非3D画风时，沿实际要求制作。

- **文字层级**：课名最醒目，年级/学科次一级，每篇用一句简短主题。大标题与场景自然融合；手机缩图先看清课名和主题，不堆说明段落或卖点列表。
- **画面主体**：让角色的表情、动作、互动和关键道具成为主体，场景铺满画面。沿本课已采用的人物、服装、场景、配色和材质；借鉴旧课的海报表达，不复制旧课角色或无关剧情。没有故事角色的课突出真实教学对象和操作，不虚构产品自带剧情。
- **系列变化**：保持同课身份与画风一致，根据各篇问题改变景别、视角、动作、主道具与文字位置。不能五张只换标题和小截图，也不机械固定篇数或五个主题。
- **制作方式**：先查看实际风格/角色参考，沿用户已选生图路线制作独立艺术封面；未指定时优先Codex内置生图。已有符合该方向且来源明确的封面直接复用。保存实际提示词、参考对应和成图；工具不可用时说明缺口，不静默改成交付截图模板。

除非用户明确选择这种样式，不用“纯色底＋小课件截图＋说明文字”的通用卡片代替故事海报。下方`dual/focus/companion`及本地排版1—4用于内容图；工具称作“封面页/首图”的拼图也不是默认艺术封面。

艺术封面可以生成，真实课件与文稿的事实画面仍按下节取源；不能把“不重画事实内容”扩大为“不做封面生图”。海报中的故事想象、空白纸张等道具不冒充实际学习单、原PPT截图或实测结论。封面若展示具体题目、刻度、条件或答案，使用真实源图等比排版，不交给生图模型重画。

## 可用画面

封面可以创作，但人物、故事、画风和数学仍应与现用课件核对。真实 PPT 页面、文稿局部、学习单、黑板贴和准确刻度图要从源文件导出或截取，等比缩放；不把它们交给生图模型重画文字、刻度、图形或答案。局部放大要保留题目条件、起终点和单位。重新排版的讲解卡写作宣传解读，不能称为产品新附件或原课件自带动画。

艺术封面和原解释卡常用3:4竖图，设计稿默认1440×1920；这是本工作流选用画布，不作为平台强制规格。默认整组图文1按[本地排版工具](local-layout-tool.md)调用排版1，图文2按[内容选版规则](note-planning.md)选2/3/4之一，图文3沿下方原解释卡制作。工具排版使用完整显示模式、真实选页及独立版本目录，保留模板原版式JPG和渲染清单；不拉伸长图去满足3:4，不把模板“封面页”或总览拼图当艺术封面。封面继续原规则。先检查完整尺寸，再看手机缩图。封面问题、内容图与正文必须回答同一主题。视频竖画布内放横向课件画面时保持原比例，不能拉伸人物或裁掉尺子两端。

第3篇用以下原解释/配套内容卡，按选题组合，不必三种全用。前两篇课件主体保留所选工具排版，可按下节增加最多1张配套卡，不用原卡替换主体：

- `dual`：两张真实页面上下对照，适合整课片段或前后对比。
- `focus`：一张真实页面/局部＋一至三条判断步骤，适合辨错或数间隔；JSON 须加`detail_title`和`details`列表。
- `companion`：主课件画面＋文稿/学习单/板贴局部及关系说明，适合配套展示。

## 少量配套内容卡

按[默认分配](note-planning.md)每篇最多1张：教学设计展示一个关键环节，逐字稿通常取2—4句引导或追问，电子黑板贴展示少量实际板贴及使用关系。配套卡紧跟对应课件图，回答本篇同一个问题；第3篇优先直接用上述`companion`组合卡，不再叠加重复卡。前两篇课件图仍走本地工具，配套卡使用现有PNG制作能力，无需改排版工具或新增接口。

- **文稿取小片段**：从实际成品导出、截取，或将同文放大排版；逐字稿保留原话与必要上下文。教学设计压缩表述时标“环节摘要”，不用引号冒充原文。不把整页Word缩成手机读不清的小字。
- **板贴展示用法**：从实际电子黑板贴成品取图，等比组合，并结合对应课件页说明摆放或分步使用。重新组合的画面标“使用示意”，不冒称已有课堂实拍、动画或产品新增附件。
- **保持来源对应**：记录实际源文件、段落/页码或板贴图号以及对应课件页；截图不裁掉题目条件、单位或改变原意。没有匹配材料时按规划注明缺口或不相关原因，不生成虚构文稿、板贴凑数。
- **核对可读性**：逐字核对摘录与源文件，查看原图和手机缩图；若文字太密，缩短摘录范围而非继续缩小字号。新配套卡在有序交付清单中标为`teaching-companion`，字段见[文案与交付检查](copy-and-review.md)。

## 复用原卡制作脚本

重复制作可调用`../scripts/render_cards.py`。脚本使用 Python 3.11+ 和 Pillow，先定位现有环境，不安装全局依赖。它只负责等比排版和保存来源哈希，不负责判断教学内容，也不自动裁切。图源先准备为准确 PNG/JPEG；需要局部图时，另存经人工检查的局部源图。输入 JSON 示例：

```json
{
  "font_regular": "C:/Windows/Fonts/msyh.ttc",
  "font_bold": "C:/Windows/Fonts/msyhbd.ttc",
  "cards": [{
    "file": "01_量法辨错.png",
    "layout": "focus",
    "kicker": "课堂难点 · 01",
    "title": "这把尺，摆对了吗？",
    "intro": "先让学生判断，再追问从哪里读起。",
    "detail_title": "怎样判断？",
    "details": ["看纸条起点对应的刻度。", "再看终点，数两端之间的间隔。"],
    "panels": [{"file": "C:/course/final-P012.png", "label": "课件 P12｜真实摆尺图"}],
    "footer": "看尺边，更要看刻度线"
  }]
}
```

命令：`python scripts/render_cards.py cards.json --output <新的绝对目录>`。字体路径必须指向本机可读取且支持所用字符的字体；脚本不会安装或打包系统字体。输出目录已有同名图或`render-manifest.json`时停止，不覆盖旧图。画布与配色可在 JSON 的`palette`中写`background`、`ink`、`muted`、`accent`十六进制颜色；不填用中性暖色初稿，最终按课程系列视觉复核。输出的`render-manifest.json`记录源文件与成图哈希。
