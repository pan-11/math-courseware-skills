# 第6篇：逐字稿＋课件截图

默认整组的本篇目录为`note-06`，形式为`image`。第1、2篇保留原图文版式，第3—5篇为视频封面文案，前五张故事海报规则保持；本篇采用浅色大字封面和内嵌PPT截图的连续逐字稿正文。单篇、指定数量或其他形式的明确请求优先，旧五篇交付不自动补做。

## 来源与内容

- 取本课当前定稿的逐字稿和对应最终PPT，先建立“课堂环节 → 逐字稿段落 → PPT页码/显示状态 → 笔记图号”映射。逐字稿页码和PPT页码分别记录，不要求数字相同。截图如取动态后显状态，要核实它对应讲到此处时的画面。
- 按原稿课堂顺序连续呈现导入、探究、练习、总结及实际存在的其他环节。保留教师原话、追问、预设回答与过渡，按手机阅读重新分段分页；仅调整排版，不改教学内容或替换为泛泛的流程提纲。
- 学生回答明确标“生（预设）”；分支回答、教师追问和活动动作依原稿保留。原稿没有的回答、课堂效果、视频对白或点击动画不得补写成既有事实。发现原稿错误或与PPT不一致时先说明并核定，不在宣传图中暗改原课。
- 没有完整、匹配的逐字稿时记录第6篇的实际缺口。其他有依据的篇目可以继续，但不能把五篇称为六篇已齐，不能用教学设计扩写师生对话冒充已有逐字稿。用户另行要求精选片段时标明展示范围，不称整课全文。

## 图序与视觉

1. **浅色大字封面**：奶油白、淡黄等浅底，清晰课名与一句课堂用途，少量划线或色块突出关键词；可保留简洁笔记本感。示例：“《课题》公开课怎么上｜逐字稿＋课件对照”。这是第6篇专用封面，不套故事海报。未有真实依据，不用“听了一节”“被夸啦”等亲历或评价表述。
2. **逐字稿正文内插图**：逐字稿原文是连续阅读主线；讲到某一PPT页时，在该处正文段落之间插入那一页的真实截图，标“PPT P03”等页码，然后接着排后续教师原话、学生预设和操作提示。例如“导入原话 → P03截图 → 对P03的追问与回答 → 转场原话 → P04截图 → 后续原话”。同一图涉及多页时逐段标清对应关系，跨图续讲保留小标题与连续序号。保留原稿内容和顺序，不改为逐页PPT解读、摘要卡或截图配几句说明，不把全部截图集中到文末。
3. **信息区分**：教师话语以黑色为主，学生预设用深蓝色，关键追问/易错提醒用深红或橙色；翻页、播放视频、实际点击出答案和板书提示可用淡黄/青色底标注。保留“师”“生（预设）”“操作”等文字标签，不能只靠颜色辨识。
4. **收尾展示**：可附少量同课真实课件总览、实际配套资料展示。根据来源和阅读需要取舍，不以总览或资料图替代连续逐字稿正文，也不照抄参考笔记的文件名、数量、店铺标记或水印。

默认使用3:4竖图，可按1440×1920制作；这是工作画布，不是平台强制规格。正文图数按原稿长度和可读性确定，不套前两篇约10张的目标，不为压缩图数删掉必要环节。正文须重新分页排版，避免把整页Word缩成小字；装订环、边框等装饰不能盖住文本或截图。逐张检查全图和手机缩图，确认文字不截断、截图不变形、页序连续。

## 制作与交付

课件画面从真实PPT导出，文稿用原生字体忠实排版；可用现有本地HTML/CSS或Pillow能力将文本、色块和截图组合成PNG，不调用生图重画文字、题目、数学或答案。只使用现有环境和字体，不安装或打包系统字体。

`render_cards.py`现有`dual/focus/companion`适合辅助卡，不是连续逐字稿渲染器；不要传入不存在的`layout: "script-illustrated"`。本篇长文本由宿主按上述规范实际排版，工作区保存原文、图序、来源映射与实际输出。`script-illustrated`仅是交付检查器识别正文图的类型。

`note-06`交`00-cover.png`、按序正文PNG、可选收尾图及`copy.md`（标题、完整正文、话题）。宣传正文说明实际展示的课堂思路与材料用途，和图片中的逐字稿区分；不把重新排版的宣传图说成原商品新增附件。

在`delivery.json`中，每张逐字稿正文图标`kind: "script-illustrated"`，同时列`courseware_source`和`script_source`，各含真实`file`及精确`ref`，多页/多段在定位中逐项对应。原件为定位依据，截取图和渲染版本的关系保存在工作区。字段示例与六篇检查命令见[文案与交付检查](copy-and-review.md#第6篇正文图来源)。

验收时逐句对原稿、逐图对PPT页及显示状态，再核课堂顺序、分色标签、手机可读性与标题真实性。机械检查只能核文件、结构和来源字段，不证明师生对话、对应页或视觉质量正确。
