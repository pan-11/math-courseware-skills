# Courseware Xiaohongshu Skill files

- `SKILL.md`: routing, scope and shared production decisions. Keep it concise.
- `agents/openai.yaml`: invocation metadata only.
- `references/`: focused instructions for product images, note planning, visual production, video-note covers/copy, optional requested editing kits, and copy/review. Read only the relevant reference during use.
- `references/product-images.md` owns the finished-products -> product-images -> note-materials handoff, actual-source detail exports, separate versioned directories and checks. `references/product-image-prompts.md` owns the three reference-based main-image prompts. Main 3 omits worksheet/sticker quantities and board-layout sets, uses “电子版黑板贴” and verified “可编辑PPT”; source inventories retain actual counts. Do not copy a seller's watermark or policies, package private lesson/reference images into the Skill, or hardcode one lesson's quantities.
- Product resource lists and descriptions include “希沃课件”, which the user explicitly promises to upload to Seewo at the end. Keep this item in all three main images, detail overviews and copy listing the product contents even before a local Seewo file exists. Record the user's promise and pending upload separately; do not invent a file, extension, link, completed upload or feature. Use real courseware previews without mislabeling them as Seewo screenshots. The user handles uploading; this rule does not authorize it.
- The accepted presentation puts PPT, Seewo, actual video backups, teacher documents, worksheets and electronic blackboard stickers in that order. Resource-only revisions edit inspected main images while preserving their artwork/layout and reuse unchanged real detail images. Product delivery includes an independent resource overview and matching `product-description.md`; keep quantities course-specific and do not require the example's row/image counts.
- `scripts/`: deterministic original card layout, the four-template local adapter (`render_layout_tool.py`, shared `layout_profiles.py`, `layout-tool-runner.cjs`, `layout-tool-preload.cjs`), and delivery checks. The adapter loads the configured external template without copying its layout implementation; it uses retained isolated runtime data. Scripts never choose teaching claims, invent source frames, or publish.
- `references/local-layout-tool.md`: local tool location, explicit job format, source/output provenance and all four content-image templates. The machine-specific settings stay outside the distributable Skill. `references/note-planning.md` owns the default whole-series distribution, content-based template selection and matched teaching-material excerpts; independent requests keep their own scope. Image posts aim for around ten images including the cover, with more than eight when relevant sources support it; do not pad insufficient material or enforce a hard count. Multiple sourced companion images may accompany each post's courseware layouts. The same finished content image may be reused across posts without a duplication quota; retain different overall topics and copy.
- `references/visual-production.md` owns lesson-segment matching and the source/export/layout method. Courseware screenshots pair with actual teaching-design, verbatim-script, lesson-presentation, worksheet, blackboard-sticker or board-layout content for that same segment. Keep the existing `teaching-companion` metadata name for compatibility. New story covers follow the selected image-generation route or reuse accepted artwork; factual content images use actual files and faithful typography, never generated replacement text, scales or answers.

This is a post-production Skill for finished courseware and actual supporting files, callable independently or from Studio after teaching products are finished. Product images precede new whole-course note materials; explicit single-note edits and notes-only requests retain their scope. It must not route through disabled `k12-courseware-*` Skills or modify source lessons. The default series keeps the three image-post rules and delivers two video-note covers with titles, body copy and hashtags only; the user produces the videos. Do not require or add shot images, editing lists, material packs, narration, subtitles or timelines in this default scope. `video-cover-copy` is the default video-note format; retain `video-edit-kit` compatibility for historical packages or explicit additional requests. All output paths must be explicit and existing files must not be overwritten silently. Keep files in English names except user-facing course output. Do not install global dependencies, delete or roll back files, or publish user content without explicit authorization. Commit and push the Skill and its repository integration files only with the user's explicit authorization.
