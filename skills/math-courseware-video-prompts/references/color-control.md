# 彩色视频的参考职责与色彩核对

用于目标是彩色视频、但导演板是黑白线稿的任务。用户明确要求黑白片或指定灰度段落时按其要求执行；不要把黑白道具、白纸、黑字或自然低饱和场景误判为故障。本规范降低参考冲突风险，不保证模型一定遵从。

## 先确定事实

- 实际查看待上传文件和已采用彩色来源，核对请求正文、图片角色及文件哈希；不能只看文件名或提示词。
- 单张失败截图只能证明该时刻的可见表现。没有原请求和完整视频，不能断言首帧选错、彩色参考未上传、全片黑白，或把截图中的任务归到当前课程。
- 在现有 `asset-list` / `style` / `upload-map` 中区分：分镜审阅板、实际生成板、色彩与材质依据、人物/场景/道具参考、实际首帧。职责写进本次完整视频词，不只留在内部记录。

## 输入选择：先减少黑白与彩色的冲突

1. **优先使用彩色生成版。**黑白板保留为导演审阅与构图来源；给彩色视频模型的完整故事板优先使用依照已采用彩色资产和同版风格描述制作的彩色版本。需要新增彩色版时，在现有导演/板组提交审阅前准备；最终视频词仍按原流程冻结风格，不制造“先采用黑白板才能做彩色板”的循环或额外固定审批轮次。已有合格彩色板直接复用，不为进入本步骤重画黑白板。彩色版仍遵守整板、稳定镜号和格外编号规则，不额外增加镜头或固定生成次数。
2. **彩色版只作忠实视觉转换。**沿当前已授权图片线路制作，逐格保留人物身份、机位、构图、动作状态、数量、文字、左右及顺序；按实际采用图恢复服装、场景、光影与材质，不能只给灰图统一套色。涉及数学判断的颜色、红黄球数量等优先遵从教材与已确认条件，不能随画风改色。不覆盖黑白源图；记录两版映射及真实哈希，新图未制作/未查看时不得标为可上传。
3. **黑白板直接作参考是有依据的选择。**用户明确要求保留该输入方式，或同入口、同类参考组合已有实际彩色结果证据时，可保留黑白板作为构图参考，同时使用必要的已采用彩色参考并写清职责。记录选择与证据，不让黑白板成为彩色成片的唯一视觉依据。出现黑白输出后先核对原请求，再改输入方案，不靠反复加强同一句否定词重抽。
4. **首帧入口另行处理。**若入口把输入图作为影片首帧，必须使用符合起始状态的实际彩色单画面；不把黑白板、彩色整板或角色三视图放入首帧位置。只有当前入口实际支持的模式和素材组合才可使用；需要调整整板上传形式时，按原有例外记录依据，不能为换色擅自拆镜、改时长或删对白。

彩色生成版是当前画风的落实，不重新选择故事或画风。其实际查看与版本展示纳入已有素材/运镜组，不另增固定审批轮次，不把旧板采用冒充新图已采用。新增图片、视频测试、返工费用及上传仍按现有授权范围执行；不得自动扩大数量或预算。

## 请求与完整提示词

- **角色比摆放顺序更明确。**核实图片处于普通参考、风格参考还是首帧位置。界面有相应职责槽位时按真实功能设置；API用官方支持的角色字段。不声称“放第一张”就是最高风格权重，不虚构权重、强制彩色开关或 `negative_prompt` 字段。
- **指定实际色彩依据。**在参考映射和冻结风格段落中填写真实文件名及可见的角色服装主色、场景主辅色、光源冷暖与材质；没有依据的精确色值不编造。黑白审阅板的线条、纸感、灰度不进入目标画风。仅上传必要参考，按实际素材数量重新核费用，不能靠删除必要角色或数学条件适配数量。
- **每个片段完整写入色彩要求。**从第一帧起持续采用目标彩色表现，跨镜不意外褪色；不添加“黑白逐渐变彩色”的过渡。保留剧本原有的时间、天气和有意光照变化，不强行增艳或改成白天。

以下是组装时需要填实的内容骨架，不是未填即可提交的提示词，也不替代五部分完整词与逐字对白：

> 本片从第一帧到结束保持【已采用的彩色媒介与材质】。人物外观和颜色依据【实际角色文件及主色】，场景配色、光照与材质依据【实际场景/画风文件及可见特征】；数学相关物体颜色严格遵从【已确认条件】。故事板【实际文件】只指定本段【镜号/格位】的构图、顺序与动作状态，不是影片首帧。若该板为黑白，仅参考其空间和动作，不继承灰度、线稿或纸张表现。全段不出现非剧情要求的黑白、灰度或褪色效果，也不从黑白过渡到彩色；成片不输出镜号、编号留白、网格或制作标签。

实际选择彩色板时删掉条件式的“若该板为黑白”说明；真正使用首帧模式时按实际彩色首帧重写其职责，不保留与请求角色矛盾的文字。最终TXT必须明确本次真实选择，不把这些分支交给视频模型决定。

## 原生模式核对示例（不是其他入口的通用参数）

2026-11-06核对的[MiniMax H3创建任务文档](https://platform.minimax.io/docs/api-reference/video-generation-v2-create)与[官方视频指南](https://platform.minimax.io/docs/guides/video-generation)区分首/尾帧图生视频与参考生成：前者使用 `first_frame` / `last_frame`，后者使用 `reference_image` 等；两类角色不能混在同一请求中。单图省略角色也可能按首帧处理，因此参考板要明确填写实际支持的参考角色。

这只证明输入语义，不证明“彩色参考＋黑白板”必然输出彩色，也不证明摆放顺序的权重。使用秘塔等服务商时仍核该入口的当前文档与请求；不得改用官方站点地址发送服务商密钥。文档中的角色支持不能代替真实上传或生成验证。

## 结果检查与修复

- 下载后检查首帧、每个镜头/转场的前后、片中与尾帧，并实际播放完整片段；记录发生黑白/褪色、服装或数学道具变色的时间位置。抽帧通过不等于全片播放通过。
- 与已采用彩色资产比对人物、服装、背景、光影和数学色彩；同时检查镜号、标题条、网格等制作信息是否泄入成片。仅有标题或背景少量彩色、人物仍灰度，不能判为目标彩色通过。
- 先核本次实际上传文件、模式、角色与提示词，而后只修有证据的问题。若输入角色正确仍出现灰度，优先切换为忠实彩色生成板，或在已核实的首帧模式使用实际彩色首帧；不得仅凭截图宣称修复原因已确定。
- 可以在已有授权范围内先生成一个原计划片段核对色彩，再继续同批其他片段；不额外增设必付费测试。失败片段保留，返工是否执行取决于当前实际授权和剩余额度。未实际生成/播放时只标“已补控制规范，效果待验证”，不得宣称已杜绝黑白。
