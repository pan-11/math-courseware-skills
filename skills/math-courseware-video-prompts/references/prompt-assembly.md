# 完整视频词、片段与上传映射

## 先核对输入能否互相对应

读取当前`director.md`，确认静态表与动态表镜号和顺序相同，构图、画面描述、景别、机位、运镜五个共享字段一致。实际查看黑白故事板，按格位核对`storyboard-map.md`中的板文件、S镜号与a/b关键帧。检查每格编号位于镜框外上方的独立白色留白区，不压边、不进入画面；格外编号与映射一致，格内无制作角标，剧情内文字保留。

核对`asset-list.md`与真实角色、场景、道具图；核对`style.md`已冻结段落的实际彩色来源、版本、SHA256与采用依据。读取完整声音稿，与动态表逐句比对。来源不全时可以做明确标注的准备稿，缺实际图、未冻结风格或未定导演不能靠假路径、猜配色或自行补镜头填成正式可提交包。

## 通用素材包与平台适配边界

课件情景视频的试片和正式片段默认用 **MiniMax H3**。优先执行用户当次明确指定的选择，其次沿用本课已记录且仍适用的设置。用户明确选择固定机位讲话等专用制作路线时，沿用相应路线。素材准备直接交付完整通用视频素材与提示词包，**不主动追问平台或模型，不主动推荐平台，不等待入口、参数或标签**。脚本、导演、实际正式板、参考资产、冻结风格、完整声音稿、每次生成的五部分全文TXT、建议上传映射及普通目录，仍按原有节点完成。内容采用、操作回传和成片检查沿原节点执行。

实际平台或入口尚未核验时，报告所用模型及“本次交付通用素材包，实际入口兼容未核验”。提示词用包内实际文件名和正式镜号指称参考，完整列明职责、建议上传顺序和板格范围，不捏造平台标签，也不等待标签才交付完整词。逐张记录实际待上传图的尺寸与比例。仅入口兼容、具体档位或标签未核验时，按实际素材完整度报告状态。

仅当用户主动提供具体入口，或主动要求该平台适配、代操作时，才核实对应的官方限制或真实界面：输入类型、单次时长/尺寸或画幅范围、参考数量/格式、声音方式、标签规则与核查日期。已主动给出的入口信息直接复用，不为完成通用包再追问平台或模型。只核本任务实际使用的参数，不建通用平台参数库，不猜品牌上限、可选档位或上传标签；必要的操作回传沿原节点集中提出。平台信息或适配要求本身不授权媒体付费生成。

默认模型只确定模型选择。声音沿用已采用稿件。具体服务入口、该入口支持的声音和技术参数仍按当期官方资料或真实界面核验。实际代操作或付费生成须满足原有工具、权限与授权要求。

## 片段划分

按完整声音与自然动作结束位置划分C01、C02等生成片段，沿用已有C编号。每片段记录所含S镜号、涉及的a/b帧、片段内起止时间、对应全片位置及估计/实测依据。总时长为所含镜头合计，不把平台上限当成剧情总长。

一个长故事板可以被多个片段复用，各段明确只执行指定镜号范围，不需要每15秒或每个片段重画一张。默认按剧情、完整声音及自然接续安排C片段和计划时长，不等待平台上限；未实测的声音与时长标为估时，具体平台档位未核验如实注明。用户要求适配且某个既定镜头无法放入已核实限制时，交导演/声音环节提供保留完整内容的有效拆分，再更新映射；组装器不私自加切镜或删台词来适配。

## 上传图片宽高比与兼容检查

检查对象是**实际要上传的每张完整图片**，包括复用的角色三视、场景多视、道具、彩色首帧和正式整板；不是只查成片画幅、板内单格或本轮新图。

1. **依据当前入口。**记录限制的实际界面/官方资料与日期。本项目2026-10-16收到的画布MiniMax H3入口报错2013明确要求`0.4 ≤ 图片宽度 ÷ 图片高度 ≤ 2.5`；沿同入口且未有更新证据时按该范围检查。此为已收到的界面限制，不推广为其他平台、其他入口或API的通用规格；有新证据按新依据核对，未知项保留待核实。
2. **先约束画布，再量真实文件。**已知限制写入完整生图词及多视/整板布局，按素材用途选择范围内留有余量的画布，例如适用的16:9或3:2横版，不固定所有素材尺寸或强改首帧画幅。生成后及交付前均读取真实文件的宽、高，计算宽÷高，在清单或同版检查记录保存文件名、尺寸、比值、限制依据及结论；请求尺寸不代表实际尺寸。例：2048×768约2.67，在上述入口超限，即使其中各视图或最终影片是16:9也不合格。
3. **只修超限项。**沿当前已授权生图线路做定向图像编辑，保留人物身份、同一场景、道具数量、所有视角/镜号与顺序；不拉伸主体、裁掉必要画面或删参考来规避限制。只有用户明确选择且授权覆盖当前素材的本地规整才执行对应操作；已有同范围授权直接沿用，不重问或扩为其他图的许可。保留旧图与真实新返回，重新检查比例及画面内容，不能把内置生图编辑声称为逐像素本地补白。
4. **同步交付与状态。**替换后更新实际来源/版本/SHA256、asset-list、upload-map、入口以及受影响的文件名、标签和板格映射；同一新图跨片复用时，各副本哈希一致。内容和引用未变的完整TXT、对白、导演及风格保留，不为技术兼容修订新增创作采用轮次。尺寸检查通过只说明符合该项限制；没有实际上传结果，不称平台已接收，也不代表最终视频已生成或验收。

## 整板上传（默认必须执行）

运镜切镜路线的最终上传方案，默认使用**一张包含本次C片段全部镜号及必要a/b状态的完整黑白故事板**，配合实际需要的角色、场景、道具和画风参考。已有清楚、格外编号合规且格内无制作角标的长板可直接复用并指定本段范围，不必另画一张；单镜单状态的现有一张图本身即可作为完整板，不添加网格或重复填格。格数、参考总数、时长均按任务决定，不固定为四格、六图或12秒。

1. **先落实真实整板。**允许逐格生成、改错和验图，但单格是制作/检查中间文件。只有单格时，由AI沿当前已授权的图片制作方式，按镜号和状态顺序整理成实际整板文件；保留原单格、构图、人物身份、数量、方向和每格画幅，不借合板重新创作。实际查看新板，逐格核查内容与可读性。编号进入画面、压边、带画内底框或格外编号缺失/错配时，先按[故事板看图与修正](../../math-courseware-video-storyboard/SKILL.md#检查与修正)整理到格外白色编号区并另存；合规格外编号不得误删。保留源图；按修正版的实际文件、格位、SHA256 同步提示词、上传表与入口。无通过检查的实图时，注明待补；画内仍有制作角标的板不得作为上传参考。网页画廊、Markdown并排展示、25格剧情预览或待生成路径都不能代替这张图片。
2. **建立板内对应。**在storyboard-map与完整视频词中写明实际板文件、格位置（例如左上/右下或第几行第几列）、格外S镜号、a/b状态及片段内时间。a/b属于同一镜头的连续动作，不因占两格增加切镜。视频词明确：格外编号仅供定位，成片只呈现指定镜框内的故事画面，不输出镜号、编号留白区、故事板网格或范围外画面；色彩与材质沿已冻结风格。
3. **同步全部上传说明。**upload-map只列当前必要彩色/设定参考与实际整板；原单格可留作修改来源，默认不重复上传。合板后同步参考数量、建议顺序、完整词的所有文件名/图号/格位置、start-here链接和清单哈希；用户主动要求平台适配时另同步已核实标签或待核项。不能只改一个文件而沿用旧单格编号。
4. **交付前检查。**普通素材文件夹内必须有可打开的实际整板、对应完整词、上传表和入口；缺整板时明确未完成项并继续已授权制作，不让用户自行拼接。用户本轮只要文字或缺工具时，可交标明“整板待制作”的准备稿，不能虚构实图或声称可提交。

只有用户明确指定单格/单镜方式，或已核实当前入口只接受首帧等限制，或实际压缩/分辨率检查证明整板不可读时，才调整上述上传形式；在upload-map说明具体原因、证据和处理。可读性问题先提高可用分辨率，仍不足再按连续镜号分成少量清楚的板，不删剧情或默认逐格上传。已有单格、制作工具一次只出单格、省时间、平台未定，都不是跳过整板的理由。固定机位讲话继续交实际彩色首帧与完整台词，不套用此规则。

## video-prompts.md的五部分

文件开头记录当前视频/版本、依据文件与SHA256、平台核实状态、各C片段顺序及总时长。随后为每个C片段提供可单独复制的完整提示词，严格包含以下五部分；每段都展开真实内容，不写“风格同上”“见导演表”或“保留原台词”。

### 1. 【声音要求】

每段明确写：**不要出现BGM，不要出现字幕，保留剧本对白和环境/动作音效。**

然后说明本段实际说话者、画内/画外关系及已有配音的使用方式。逐字台词在第五部分完整出现，不能因“不加配乐”或音效列为“无”而消除对白。无对白片段如实写无对白；不为了有声增加新解说。

### 2. 【真实参考映射】

按包内实际文件名逐项说明本段职责与允许影响：

| 参考类型 | 必须说明的职责 |
|---|---|
| 角色参考 | 锁定人物身份、服装、比例和特征；正侧背图不作为成片三联画 |
| 场景参考 | 锁定地点、设施布局、色彩与环境；默认是设定参考，不自动当视频首帧，也不逐帧照搬场景图 |
| 道具参考 | 锁定本段可见道具的造型、结构和必要数量 |
| 黑白故事板 | 格外编号只供定位，控制指定镜框内的构图、顺序和关键状态；成片不输出编号、白色编号区、黑白网格、箭头或底部参考区 |
| 明确的实际首帧 | 只有用户/上游明确指定为当前片段首帧，且平台入口已核实时才承担起始画面职责；与普通场景设定图区分 |
| 实际音频 | 仅在已取得文件且当前入口真实支持时说明对应说话者、时间范围和用途 |

同一文件可在多段复用，但每段仍写实际职责和镜号范围。标签与文件的关联以`upload-map.md`为准；不能用不存在的上传编号代替真实文件名。

### 3. 【统一风格原文】

逐字复制当前`style.md`的冻结固定段落，每个片段完全一致。不得在不同片段中改写媒介、材质、色板或角色比例；有剧情依据的局部光照变化放在对应镜头内容，不擅改全片风格。

目标为彩色视频时，在每次生成的完整提示词中，紧接固定风格原文加入以下约束；将占位内容填成已采用彩色参考的实际特征，每段完整展开。沿用原来的黑白故事板和彩色角色、场景、道具参考及上传流程，不要求另做彩色电影分镜。

> 从第一帧到最后一帧，所有镜头持续采用已确认的彩色画风【实际风格与材质】。人物的肤色、发色、服装颜色以及环境、道具的配色，严格依据本段对应的彩色角色、场景和道具参考【实际文件及主要颜色】；教学对象的颜色与数量保持已确认条件。黑白电影分镜仅用于构图、站位、动作状态和镜头顺序，其灰阶、线稿和纸张底色不是影片的视觉风格。全段保持完整彩色，不生成黑白、灰度或褪色画面，不出现从黑白转为彩色的过渡。只呈现完整故事场景，不显示分镜编号、白边、网格或参考拼图。

按本段实际涉及的角色、场景与道具填写，不加入无关对象；已确认的特殊色彩剧情按其原设定处理。上述文字是生成约束，不是效果保证；成片按用户人工检查的约定执行，不新增自动审片环节。

若只有候选风格，准备稿明确写候选及依据，整体状态保持未冻结，不标为正式可提交。黑白故事板不决定最终配色。

### 4. 【指定故事板与状态接续】

明确本段使用哪张真实板图、各镜在板中哪个位置、执行哪些S镜号和a/b关键帧，按什么顺序展开。写明本段开始状态、上一段结束状态的继承、各镜自然接续以及本段停止状态；根据导演记录填写具体位置、视线、运动方向、物件和声音延续，不新编故事。

区分“同镜a/b状态变化”和“两个镜头切换”。复用长板时明确不生成本段范围以外的其他镜头，不能把整张板作为一帧拼图输出。首段不虚构不存在的上一段，末段不添加教师接话。

### 5. 【对应动态镜头全文】

逐镜展开当前动态表全部内容，至少写：

- S镜号、片段内开始—结束时间、镜头时长，以及估计/实测依据。
- 构图、画面描述、景别、机位、运镜：逐项保留当前表值，与同镜静态表一致。
- 台词：说话者、语气、画外标记及完整逐字内容；无对白则写无对白。
- 动作：起始状态→动作/反应→结束状态。
- 节奏：观察、动作、停顿和切换的顺序与时间关系。
- 音效：该镜已有的具体环境和动作声音。

可把表格改为连续段落以适应平台输入，但内容不得摘要化、漏字段或改含义。片段内时间从实际顺序计算，不让相邻镜头重叠或无故留空；所有台词在整段视频实际执行中出现一次。若平台有文本长度限制，先核实再处理；不能静默删对白、动作或必要参考说明。

## start-here.md与交付检查

`start-here.md`是该普通素材文件夹的唯一入口，包含当前路线和状态、实际使用文件、按C片段顺序的操作、平台兼容状态、AI尚未完成项、当前是否存在真实成片；用户主动要求平台适配时另列本次待核参数。链接使用本文件夹内真实文件；不另建互相矛盾的入口，不把历史ZIP作为入口。

每个C片段另存独立完整TXT，正文与video-prompts.md对应段一致，入口逐次直链。聊天先写[共同回复开头](../../math-courseware-studio/references/reply-contract.md)，再按[视频正文模板](delivery-reply.md#唯一固定模板)排平台/模型、总入口、编号图片表、逐次完整TXT表、表后各片目录、操作与真实状态；不重复步骤/产物开头。总MD/网页不能代替每次TXT直链和两表，准备稿与修订补交同样执行。

最终核对：

1. 需求和剧本事件均有对应镜头；组装没有新编或漏掉事件。
2. 全部逐字对白在实际执行片段中恰好出现一次，完整声音可容纳于时长；估计与实测分开。
3. S镜号、板格/a/b映射、实际图片和动态表一致，五个共享字段没有被改写。
4. 每段五部分完整；固定风格逐字相同，引用真实文件及其正确职责。
5. 上传文件存在、可读且版本/哈希一致；实际整板覆盖本段全部镜号/状态，或有明确例外依据；参考数量、图号、格位置与所有说明一致，平台兼容状态显式标记；用户主动要求适配时另列本次待核项。

必需实图/文本齐备且同版采用/审阅依据有效时，可交付“完整准备稿（通用素材包）”；平台未提供不降低为部分准备稿。仅当用户主动要求平台适配且当前平台实际参数和标签也已核实后，才可标记针对该入口的“可提交”。“可提交”仍不代表已提交、已生成视频、已获用户采用或已验证实际观赏效果。
