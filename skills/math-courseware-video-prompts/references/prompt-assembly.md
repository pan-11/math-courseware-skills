# 完整视频词、片段与上传映射

## 先核对输入能否互相对应

读取当前`director.md`，确认静态表与动态表镜号和顺序相同，构图、画面描述、景别、机位、运镜五个共享字段一致。实际查看黑白故事板，核对`storyboard-map.md`中的板文件、格位置、S镜号与a/b关键帧；不能仅凭文件名断言图中内容正确。

核对`asset-list.md`与真实角色、场景、道具图；核对`style.md`已冻结段落的实际彩色来源、版本、SHA256与采用依据。读取完整声音稿，与动态表逐句比对。来源不全时可以做明确标注的准备稿，缺实际图、未冻结风格或未定导演不能靠假路径、猜配色或自行补镜头填成正式可提交包。

## 平台核实与片段划分

记录当前选定平台、模型/入口（若已知）、真实可用输入类型、单次时长/尺寸或画幅范围、参考数量/格式、声音方式、标签规则、所依据的官方页面或用户界面及核查日期。只填写本任务确实要用到的参数，不建立通用平台参数库，不写死某品牌上限。

平台未知时仍完成镜头内容、对白、风格和包内文件映射；引用标签写为明确待替换的说明，例如“待核实：角色参考在当前入口中的引用标签”。不能捏造`@图1`等平台语法并声称可直接提交。真实界面可用的上传顺序未核实时标“建议顺序，待平台核实”；文件本身及其职责仍须准确。

按完整声音与自然动作结束位置划分C01、C02等生成片段，沿用已有C编号。每片段记录所含S镜号、涉及的a/b帧、片段内起止时间、对应全片位置及估计/实测依据。总时长为所含镜头合计，不把平台上限当成剧情总长。

一个长故事板可以被多个片段复用，各段明确只执行指定镜号范围，不需要每15秒或每个片段重画一张。若某个既定镜头无法放入已核实限制，交导演/声音环节提供保留完整内容的有效拆分，再更新映射；组装器不私自加切镜或删台词来适配。

## 整板上传（默认必须执行）

运镜切镜路线的最终上传方案，默认使用**一张包含本次C片段全部镜号及必要a/b状态的完整黑白故事板**，配合实际需要的角色、场景、道具和画风参考。已有清楚长板可直接复用并指定本段范围，不必另画一张；单镜单状态的现有一张图本身即可作为完整板，不添加网格或重复填格。格数、参考总数、时长均按任务决定，不固定为四格、六图或12秒。

1. **先落实真实整板。**允许逐格生成、改错和验图，但单格是制作/检查中间文件。只有单格时，由AI沿当前已授权的图片制作方式，按镜号和状态顺序整理成实际整板文件；保留原单格、构图、人物身份、数量、方向和每格画幅，不借合板重新创作。实际查看新板，逐格核查内容与可读性。网页画廊、Markdown并排展示、25格剧情预览或待生成路径都不能代替这张图片。
2. **建立板内对应。**在storyboard-map与完整视频词中写明实际板文件、格位置（例如左上/右下或第几行第几列）、S镜号、a/b状态及片段内时间。a/b属于同一镜头的连续动作，不因占两格增加切镜；成片执行各镜，不输出故事板网格、镜号或范围外画面，色彩与材质沿已冻结风格。
3. **同步全部上传说明。**upload-map只列当前必要彩色/设定参考与实际整板；原单格可留作修改来源，默认不重复上传。合板后同步参考数量、顺序、真实标签或待核实标记、完整词的所有图号/格位置、start-here链接和清单哈希，不能只改一个文件而沿用旧单格编号。
4. **交付前检查。**普通素材文件夹内必须有可打开的实际整板、对应完整词、上传表和入口；缺整板时明确未完成项并继续已授权制作，不让用户自行拼接。用户本轮只要文字或缺工具时，可交标明“整板待制作”的准备稿，不能虚构实图或声称可提交。

只有用户明确指定单格/单镜方式，或已核实当前入口只接受首帧等限制，或实际压缩/分辨率检查证明整板不可读时，才调整上述上传形式；在upload-map说明具体原因、证据和处理。可读性问题先减少板内文字、提高可用分辨率，仍不足再按连续镜号分成少量清楚的板，不删剧情或默认逐格上传。已有单格、制作工具一次只出单格、省时间、平台未定，都不是跳过整板的理由。固定机位讲话继续交实际彩色首帧与完整台词，不套用此规则。

## video-prompts.md的五部分

文件开头记录当前视频/版本、依据文件与SHA256、平台核实状态、各C片段顺序及总时长。随后为每个C片段提供可单独复制的完整提示词，严格包含以下五部分；每段都展开真实内容，不写“风格同上”“见导演表”或“保留原台词”。

### 1. 【声音要求】

每段明确写：**不要出现BGM，不要出现字幕，保留剧本对白和环境/动作音效。**

然后说明本段实际说话者、画内/画外关系及已有配音的使用方式。逐字台词在第五部分完整出现，不能因“不加配乐”或音效列为“无”而消除对白。无对白片段如实写无对白；不为了有声增加新解说。

### 2. 【真实参考映射】

按包内实际文件名逐项说明本段职责与允许影响：

| 参考类型 | 必须说明的职责 |
|---|---|
| 角色参考 | 锁定人物身份、服装、比例和特征；正侧背图不作为成片三联画 |
| 场景参考 | 锁定地点、设施布局、色彩与环境；默认是设定参考，不自动当视频首帧，也不逐帧照搬场景图 |
| 道具参考 | 锁定本段可见道具的造型、结构和必要数量 |
| 黑白故事板 | 只控制指定镜号的构图、顺序和关键状态；成片不要黑白网格、镜号、箭头或底部参考区 |
| 明确的实际首帧 | 只有用户/上游明确指定为当前片段首帧，且平台入口已核实时才承担起始画面职责；与普通场景设定图区分 |
| 实际音频 | 仅在已取得文件且当前入口真实支持时说明对应说话者、时间范围和用途 |

同一文件可在多段复用，但每段仍写实际职责和镜号范围。标签与文件的关联以`upload-map.md`为准；不能用不存在的上传编号代替真实文件名。

### 3. 【统一风格原文】

逐字复制当前`style.md`的冻结固定段落，每个片段完全一致。不得在不同片段中改写媒介、材质、色板或角色比例；有剧情依据的局部光照变化放在对应镜头内容，不擅改全片风格。

若只有候选风格，准备稿明确写候选及依据，整体状态保持未冻结，不标为正式可提交。黑白故事板不决定最终配色。

### 4. 【指定故事板与状态接续】

明确本段使用哪张真实板图、各镜在板中哪个位置、执行哪些S镜号和a/b关键帧，按什么顺序展开。写明本段开始状态、上一段结束状态的继承、各镜自然接续以及本段停止状态；根据导演记录填写具体位置、视线、运动方向、物件和声音延续，不新编故事。

区分“同镜a/b状态变化”和“两个镜头切换”。复用长板时明确不生成本段范围以外的其他镜头，不能把整张板作为一帧拼图输出。首段不虚构不存在的上一段，末段不添加教师接话。

### 5. 【对应动态镜头全文】

逐镜展开当前动态表全部内容，至少写：

- S镜号、片段内开始—结束时间、镜头时长，以及估计/实测依据。
- 构图、画面描述、景别、机位、运镜：逐项保留当前表值，与同镜静态表一致。
- 台词：说话者、语气、画外标记及完整逐字内容；无对白则写无对白。
- 动作：起始状态→动作/反应→结束状态。
- 节奏：观察、动作、停顿和切换的顺序与时间关系。
- 音效：该镜已有的具体环境和动作声音。

可把表格改为连续段落以适应平台输入，但内容不得摘要化、漏字段或改含义。片段内时间从实际顺序计算，不让相邻镜头重叠或无故留空；所有台词在整段视频实际执行中出现一次。若平台有文本长度限制，先核实再处理；不能静默删对白、动作或必要参考说明。

## upload-map.md

按片段列出精确文件映射：

| C片段 | 上传顺序及核实状态 | 包内实际文件名 | 文件用途 | 角色/场景/镜号范围及板内格位置 | 平台真实标签或待替换项 | 版本/SHA256 |
|---|---|---|---|---|---|---|

已知平台按实测/官方说明写顺序和标签，未知平台按建议顺序列完整文件并标明待核实。不能混用同名不同版本的图；复制后的SHA256须与清单匹配。未使用的参考留在素材文件夹可以，但不塞进当前片段的上传列表增加歧义。

故事板项指向当前实际整板，覆盖本段全部镜号与必要状态；若按上面的例外调整分板，另写具体依据和每张板的连续范围。不能因单格文件均已存在，就把它们逐项列出并宣称最终上传包完成。

## start-here.md与交付检查

`start-here.md`是该普通素材文件夹的唯一入口，包含当前路线和状态、实际使用文件、按C片段顺序的操作、待核实参数、AI尚未完成项、当前是否存在真实成片。链接使用本文件夹内真实文件；不另建互相矛盾的入口，不把历史ZIP作为入口。

每个C片段另存可独立复制的完整TXT，正文与`video-prompts.md`对应段完全一致，并在入口逐次链接；最终聊天按[统一交付回复](delivery-reply.md)展示视频序号/开工状态、编号实图与逐次生成两表、素材文件夹及必要说明。总文件或网页不能代替逐次TXT与聊天正文表格。

最终核对：

1. 需求和剧本事件均有对应镜头；组装没有新编或漏掉事件。
2. 全部逐字对白在实际执行片段中恰好出现一次，完整声音可容纳于时长；估计与实测分开。
3. S镜号、板格/a/b映射、实际图片和动态表一致，五个共享字段没有被改写。
4. 每段五部分完整；固定风格逐字相同，引用真实文件及其正确职责。
5. 上传文件存在、可读且版本/哈希一致；实际整板覆盖本段全部镜号/状态，或有明确例外依据；参考数量、图号、格位置与所有说明一致，平台待核实项显式列出。

只有必需实图/文本齐备、同版采用/审阅依据有效、当前平台实际参数和标签已核实后，才可标记“可提交”。“可提交”仍不代表已提交、已生成视频、已获用户采用或已验证实际观赏效果。
