# 课件情景视频制作

把教学情境逐步做成可制作、可检查、能接回课堂的视频。用户可以只有课题和大致情境；故事、素材清单、分镜和提示词由AI协助形成，不要求用户先准备完整故事或填完空表。

## 先判断从哪里继续

读取课件项目AGENTS、HANDOFF及[项目协议](../math-courseware-studio/references/project-contract.md)，核对已有文件与确认依据。只读当前阶段所需资料，不重新调查已定内容。

| 当前材料 | 本轮先做什么 | 何时再补材料 |
|---|---|---|
| 只有大致情境，没有故事 | 调用[方案模块](../math-courseware-plan/SKILL.md)，给出具体故事候选和推荐稿：人物、目标、困难、因果事件、数学问题、学生行动 | 关键教材数据缺失时只问影响内容的缺口；可以用明确标注的自拟示例讨论，不能冒充原题 |
| 有故事，未定稿 | 沿现有方向补清事件与数学关系，呈现可审阅稿；不换一套故事 | 正式制作前确认当前故事/数学核心 |
| 故事与数学已确认，没有视频剧本 | 直接写表演动作、完整声音稿、结束状态和教师接话 | 不要求先完成PPT或角色图片 |
| 已有剧本或图片 | 核对版本，从缺少的素材、分镜或操作包继续 | 对应片段正式生成前才要求实际参考文件 |
| 已有候选视频或成片 | 按[回传与恢复](references/handoff.md)检查、修订、回填 | 只有文件名或口头描述，保持待回传，不能登记成片通过 |

共享故事、教学事实及核心数据归方案模块；本模块负责怎样演、怎样拍、怎样制作。只改运镜不改故事；改事件、台词含义或数学条件时先回流共同记录，不能维护两套互相矛盾的剧情。

## 制作顺序

读取[制作流程](references/production.md)。需要实际写材料时使用[输出模板](references/templates.md)，由AI填写已有内容、给具体草稿和缺项处理办法，不把模板原样交还用户。

1. 明确视频教学用途、学生观看后的任务和停止点；视频数量随教学需要，不逐页配片。
2. 写可表演剧本与逐字声音稿。对白、旁白、教师现场话语分开；台词试读或实际配音决定时长。
3. 选讲话、故事事件、数学过程路线；准备本次小样够用的共享素材和必要视角。
4. 分清课堂视频V01、镜头V01-S01、生成片段V01-C01，分别写静态画面、动作运镜、声音和段间接续。
5. 做一个代表片段的完整操作包：实际平台模式、上传文件及用途、可复制提示词、声音输入、检查项目。资料不足标为准备稿，列出补齐动作。
6. 在用户已授权的工具与费用范围内生成小样，审阅实际结果后扩展；无可调用工具时交付人工操作包并等待回传。
7. 剪辑、核对最终声音与数学、记录实际文件，再回填教学节点、PPT页面和文稿。页面未定保留待关联。

正式素材生成沿用当前项目的[生图线路](../math-courseware-studio/references/image-routing.md)。本Skill不内置视频API、配音或剪辑器；先核实当次可用工具和平台能力，不把Grsai生图命令当成视频命令，不自动安装或消费额度。

## 检查与交付

- 沿用当前版本已有确认。首次故事/数学定稿、声音内容及小样效果需要具体稿或实际结果作为确认对象；已授权的普通制作修订继续执行，不逐镜头反复请示。
- 构图故事板与角色/场景外观参考分工明确。讲话片可不做故事板；格数、镜头数、时长和模型上限不写死。
- 数量、分组、单位、算式、数轴和推理结论用可控图层/后期叠加核准；提示词约束和API成功不能证明数学正确。
- 导入或任务片把需要探究的结论留到课堂；探究后的复盘片允许呈现正确答案。教师现场接话不进入视频音轨。
- 缺图不阻断故事与剧本；缺实际文件不能声称已生成、已配音、可直接上传或成片已通过。

每轮交付实际完成的文件、当前状态、还缺什么、由谁完成及下一步。保存与单独打包按[回传与恢复](references/handoff.md)，更新HANDOFF；`collect`当前不收视频，不能只注册文件就宣称已纳入课件交付。
