# 小学数学AI赋能课件总入口

把原课件转为教学一致、视觉连续、能继续修改的一套课件。整套含十二个Skill：课程总入口、分析/方案/页面/可编辑/文稿、视频总入口及其五个专业Skill。本入口管理课程流程、版本和衔接，不代替专业创作。

**从头使用整套Skill制作课件，情景视频为必做环节。** 用旧PPT作参考、从分析开始重新制作整课，也属于此范围。不另问“要不要视频”，也不默认改为可选、静态图或教师代读。数量按教学需要，至少一段；仅校正已有PPT、单独制作文稿等局部任务按实际范围执行，用户明确调整范围时记录其依据。

## 启动与恢复

1. 先读工作目录AGENTS.md、HANDOFF.md；已存在项目执行`status`和`validate`，不因换对话另建项目。
2. 新课项目使用`scripts/courseware.py init --project <绝对路径> --title <课题>`，目录规则由初始化器先写入。可同时指定`--route builtin`或`--route openai_image_api`；已明确选择的线路直接记录，无需重问。
3. 读取[项目协议](references/project-contract.md)，只在需要生图时读[生图线路](references/image-routing.md)，发生修改、中断或等待回传时读[恢复规则](references/recovery.md)。
4. 脚本依赖Python、Pillow、python-pptx、python-docx、pypdf、ReportLab；先用Codex的运行时发现工具定位现有环境，再运行`doctor`。缺依赖先报告，不自动安装全局依赖。

## 按实际进度调用

| 工作 | 相邻Skill入口 | 开始条件 |
|---|---|---|
| 原材料分析 | [analyze](../math-courseware-analyze/SKILL.md) | 有原课件或用户明确的制作资料 |
| 情境和共享图片资产 | [plan](../math-courseware-plan/SKILL.md) | 数学任务、改编边界已分析 |
| 情景视频 | [video](../math-courseware-video/SKILL.md) | 整课从头制作必须进入；故事/数学确定后，先完成整课视频方案和制作流程 |
| 逐页内容和图片 | [pages](../math-courseware-pages/SKILL.md) | 视频方案与流程已完整交接并确认，故事数学核心、风格及实际资产可用；页数预算含视频页 |
| 可画与原生文字 | [editable](../math-courseware-editable/SKILL.md) | 确认图片课件后，先询问A/B路线并等待明确选择；再制作交接与拆层回填 |
| 配套教学文稿 | [documents](../math-courseware-documents/SKILL.md) | 已锁定图片课件或最终课件 |

已有可靠中间成果可以从相应模块接入，先登记来源和版本。不得伪造跳过阶段的完成记录。

从头整课只有“某课题＋大致情境”时，先提取教学目标与不可变数学，plan负责课程共同故事与教学节点，video-writer把视频想法写成可见事件和剧本；已有情境不强制重选。单独视频直接交video从粗情境开始，不先要求整套教学方案。缺关键教材数据只列必要缺口，不要求用户先写故事或准备图片。

从头整课顺序是：分析→共同故事/数学→整课视频创作与准备→逐页文案（含视频页）→页面生图→可编辑与文稿→成片回填及播放检查。视频内部六步为剧本/25格预览→图片资产→导演→黑白板→固定风格→完整视频词；plan的封面风格与共享资产可在视频第二步协同完成，已有图直接复用，不能把依赖资产推迟到导演和制板之后。视频先关联教学节点/预留页数，排页时再补page_id/order。

**进入PPT逐页制作前，逐项检查[视频方案前置清单](references/video-integration.md#ppt开工前的视频方案检查)。** 只写video_nodes简述、只完成一个小样操作包或说“后面再做视频”，均不算通过。材料完整后成组展示，沿用同版已有确认和视频侧两组创作审阅，不重复逐表审批；确认前不开始逐页文案、PPT页面生图或可编辑制作。方案与流程通过后，实际成片生产可与PPT并行，视频待办持续保留；素材、平台、费用和成片状态如实记录。

## 确认与持续执行

按组呈现：情境方向→共同故事/数学核心→视频剧本与预览→风格/封面参考和共享资产（视频第二步协同）→导演与正式故事板、固定风格及完整视频词→课程侧视频前置核对→逐页文案→带字图片试样→整套图片→可编辑A/B路线选择→真实回传→整套文字回填与逐页检查→可编辑稿；视频实际生成的小样与成片按其真实进度审阅。回传后的文字坐标/样页不设前置确认，直接完成整套。可编辑路线选择仍是强制停止节点：执行[editable的路线询问](../math-courseware-editable/SKILL.md)，未收到明确选择前不去字、不生成路线交接包、不调用拆层或回填；“继续”和B推荐均不能代替选择。只有用户明确要求才制作A/B对比。沿用用户在本项目已给、范围未变的明确选择，不为同版重复提问。文稿自审后交付，不新增文稿最终审批。

保存文件、自检通过、API返回成功都不等于用户定稿。确认绑定具体内容和文件哈希，记录真实用户依据；不要以自己的总结冒充用户原话。用户明确的纠错可执行并登记，无须重复申请同一修改。

选择B后，必须完成当前课件全部页面的去字图，检查并确认后按`pages.order`一页一图汇入同一个完整PPTX，同时交付同序PDF与映射清单。不得只做部分去字样页、只交图片目录，或等少量页可画回传才补余页；完整页数、页序和嵌图检查按[editable交接规范](../math-courseware-editable/references/canva-handoff.md)执行。

主控串行写共用记录；独立生图任务最多并发6路。每完成一个模块或改变方案，更新课件HANDOFF：目标、产物、检查、未完成事项、下一步。

视频先完成整课准备资料，再按当前所需素材、小样和实际成片推进，沿用相同内容的确认。plan负责共同故事与数学，video负责表演和制作；改变核心内容先回流共同记录，再同步页面与文稿。25格只用于剧情预览，正式镜头/板格/视频数和模型不写死。PPT动画由用户在WPS手动设置。等待可画回传时可以生成配套文稿。

进入视频素材制作后按两路执行：单角色固定镜头讲话，AI生成实际彩色首帧和完整台词供即梦数字人使用，不增加运镜、切镜或故事板；需要运镜切镜，AI生成实际黑白故事板和对应分镜词。复用或沿已选线路补齐所需角色/场景三视图，图片、提示词、台词和说明集中到同一个普通素材文件夹，直接交付文件夹及文件链接，不自动压缩。视频平台未定不阻断已定图片制作，不能只交提示词让用户自己生图；用户明确只要方案或工具不可用时，记录真实范围和缺项。图片包与成片完成分开验收，详见[视频实际素材制作](../math-courseware-video/references/production.md#4-自动制作实际素材)。

## 交付

课堂观看任务、教师接话、预留页、成片回填和播放由本入口协调plan/pages/documents/editable，统一按[视频与整课衔接](references/video-integration.md)执行；不要求视频编剧或导演为此新增课堂活动段落。

课件产物执行`collect`；视频按[独立清单](../math-courseware-video/references/handoff.md)复制并核对，当前collect不收视频。按实测说明“制作准备包”“成片已检查”“WPS播放已检查”等不同状态。只有真实课程贯穿流程且相关人工检查完成才称首课验收完成。发布、安装全局依赖、密钥配置和删除按用户授权处理。

从头整课交付还必须逐项核对：全部必做视频实际成片、PPT中对应视频页与独立播放区域、实际插入/播放方式、片尾教师接话及三文稿一致。仅有占位页或教师代读时，可以交付“静态阶段稿（视频待回填）”，不得标为整套制作完成。无可用视频工具时先交完整人工制作操作包，继续已满足前置条件的PPT工作，成片回传与播放核查列为未完成事项。
