# 每课五目录与保存地址

适用于整课、独立模块、自动推进、独立审核、商品图和课件笔记的文件归位。只规定保存位置，不改变本次制作范围、采用节点或实际完成条件。新课默认五个中文目录；已有课程按实际状态识别原布局，不自动迁移。

## 开工先绑定本课根目录

用户在每课开始时提供的课程文件夹就是本课根目录。只有原PPT文件、分散资料或网络链接时，先区分输入位置与课程根；根目录不明才问保存地址，不擅自选公共父目录。同课恢复沿用已登记位置，不另建一课。

先读根目录的`AGENTS.md`、`HANDOFF.md`和文件清单，再初始化或续作：

```text
courseware.py init --project <用户指定的课程根目录绝对路径> --title <课题> --layout five-folders
```

`--project`始终指课程根，不指“中间文件”或“原始资料”。先使用现有运行时定位Python，不写死机器解释器或示例课路径。新课由初始化器先写目录规则，建立五个顶层目录；已有同名目录和其中的普通文件继续使用，缺少的目录才创建。重复初始化不重写现有状态、交接、采用和原文件；已初始化五目录课可补齐缺少的顶层目录。

同名路径实际是文件、预定工作子目录被文件占用，或存在相互冲突的运行状态时，先报告具体位置，不覆盖。未初始化但已有普通中间资料可以接入；非空的内部`中间文件/_state`若没有有效项目记录，须先核其来历，不能重置为新课。发现旧生产区或两套已初始化状态也不自动合并。原件仍在根或外部时按需原样复制到“原始资料”，记录来源和哈希，原位置保留。

## 五类实际位置

```text
<course-root>/
├── AGENTS.md
├── HANDOFF.md
├── 原始资料/
├── 中间文件/
│   ├── planning/
│   ├── assets/
│   ├── videos/
│   ├── slides/
│   ├── editable/
│   ├── documents/
│   ├── interactive/
│   ├── notes/
│   ├── readable/
│   ├── deliveries/
│   └── _state/
├── 最终产品/
│   ├── README.md
│   └── v001/
├── 笔记素材/
│   ├── README.md
│   └── v001/note-01/
└── 商品详情/
    ├── README.md
    └── v001/
```

子目录按任务需要先声明用途再创建；内部技术目录沿用英文名。根另放规则与交接，已有原文件不因整理删除。独立任务只制作所需内容，不因目录齐全扩成整课；目录存在不代表产品已完成。

| 区域 | 内容与边界 |
|---|---|
| `原始资料` | 原课件、教案、逐字稿、学习单、教材图、参考视频等原样文件或副本。提取文字、页图、抽帧属于加工结果，放中间文件。 |
| `中间文件` | 分析/蓝图、资产与页面版本、剧本/分镜/提示词、回传视频和PPT、文稿源稿、互动源码、商品图与笔记制作过程、阅读版及全部状态/审核记录。保留中间资料，不当作可随手清理的缓存。 |
| `最终产品` | 已按原有要求核对、可供老师使用的PPT、课堂视频、三份教师文稿、学习单、电子版黑板贴、互动网页及使用依赖/说明。待回填或未核阶段稿留工作区；不新增逐文件批准。 |
| `笔记素材` | 按篇成包的封面、顺序内容图、标题、正文和话题。默认两篇视频只交封面文案、视频由用户制作；明确另需剪辑包/成片时才加入其实际产物。 |
| `商品详情` | 三张商品主图、按序详情图、离线预览、来源清单与使用说明。完整提示词、工具返回、静态导出和拼版过程留中间文件。 |

平台回传视频和可画回传PPT是制作输入，分别归`中间文件/videos`与`中间文件/editable/returned`。教学成片的交付副本归最终产品，宣传用素材归相应笔记；黑板贴源稿归工作区，老师使用的透明素材/PPT/PDF归最终产品。

## 文件操作与记录路径

共用JSON和专业参考继续使用**逻辑路径**，由程序展开为当前布局的实际路径；不要直接把逻辑路径拼到课程根来读写或生成点击链接。

| 记录/参考中的逻辑路径 | 新五目录课的实际位置 |
|---|---|
| `inputs/...` | `原始资料/...` |
| `planning/...`、`assets/...`、`videos/...`、`slides/...` | `中间文件/`下同名目录 |
| `editable/...`、`documents/...`、`interactive/...`、`notes/...`、`readable/...` | `中间文件/`下同名目录 |
| `_state/...` | `中间文件/_state/...` |
| `deliveries/...` | `中间文件/deliveries/...`，仅控制器收集暂存 |
| `03_final/...` | `最终产品/...` |
| `04_notes/...` | `笔记素材/...` |
| `product-images/...` | `商品详情/...` |
| `AGENTS.md`、`HANDOFF.md` | 根目录同名文件 |

Python用`state.resolve(project, logical_path)`读取磁盘路径，用`state.relative_path(project, disk_path)`获得稳定记录路径。普通文件工具和交付链接使用实际绝对路径；流程、来源、采用目标和产物引用沿逻辑路径保存。`_state/math.json`等身份不因中文目录而改变；工作区自身的AGENTS/HANDOFF与根规则分开。

新五目录课也接受旧示例中的`01_source/...`、`02_work/...`、`03_final/...`、`04_notes/...`路径别名，分别映射到前四个中文目录，不另建一套英文目录。旧商品图别名`04_notes/product-images/...`映射到`商品详情/...`；商品制作过程`notes/product-images/...`仍在工作区。绝对路径必须指向本课实际位置，别名转换只用于相对记录路径。

CLI/API省略`--layout`保留旧脚本兼容行为；**本套Skill为新课必须显式传`--layout five-folders`**。布局按磁盘上的真实项目记录检测，不靠手改字段迁移。所有专业模块、自动队列和审核共用同一课程根及路径解析。

## 交付与版本

用户使用的配套成品文件必须中文命名（三教师稿、学习单、电子板书/贴片、打印版、尺寸表与说明），按[中文成品文件名](../../math-courseware-documents/references/delivery-materials.md#中文成品文件名)执行。内部技术目录、脚本和状态记录的英文命名约定不适用于这些用户成品；交付副本改名须同步入口/下载链接及清单，保留内部来源和旧版本。

1. 工作区保留可编辑源、输入、完整版本和核查证据，按`v001`、`v002`续作，不覆盖旧版本，也不自动删除。
2. `collect`包含参考图、提示词及部分制作输出，仅在`中间文件/deliveries`暂存；不把它直接当成最终产品，也不宣称它自动收齐所有配套。
3. 已核教学产品和依赖按清单原样复制到`最终产品/vNNN`；笔记按篇放`笔记素材/vNNN/note-NN`；三张商品主图与详情放`商品详情/vNNN`。核来源/副本哈希和课件、视频、文稿页码及素材版本一致性。
4. 三个交付区各自的`README.md`标当前有效版本、文件清单、用法及仍需用户操作事项。来源换版时检查受影响的商品图与笔记；修改时间最新不等于已采用。
5. 最终包含承诺的播放/网页依赖，离线链接随包可用，记录实际PPT媒体方式和显示/播放检查，不能依赖工作区路径宣称可直接交给老师。
6. 本课阅读稿归`中间文件/readable`，运行/审核证据归`中间文件/_state`。Skill源码、通用手册和开发测试留开发仓库，不复制到每课。

商品图仍按[专门规则](../../courseware-xhs-studio/references/product-images.md)在课件及配套完成后、笔记素材前制作。工作目录为`中间文件/notes/product-images/vNNN`，成品为`商品详情/vNNN`，不占用笔记篇目目录。三个交付区只在实际交付时建立版本/README；初始化空目录不补造完成记录。

## 已有课程与接力

- 检测到`中间文件/_state/project.json`：五目录课，复用当前目录与记录，init只补缺少的顶层目录。
- 检测到`02_work/_state/project.json`：旧four-folders课，继续`01_source/02_work/03_final/04_notes`及原记录；商品图仍可放原`04_notes/product-images/vNNN`。
- 检测到根`_state/project.json`：旧legacy课，继续根下原inputs/planning/videos等布局与真实交付位置。
- 多个上述记录同时存在：明确报告冲突，不按日期猜选或重建；没有记录但存在不明旧生产区时先核实。

即使init指定five-folders，已有有效旧课也不改布局、不添另一套中文目录、不改旧文件/审核路径。只有明确要求整理某旧课时，才另做来源/目标与引用方案，经实际核对后处理；本改造不提供自动迁移命令。

**课程根**`HANDOFF.md`记录本课实际布局、当前已采用文件、候选文件、教学产品/商品图/笔记版本、等待输入和下一步；目标约100行，不逐次无限追加全文。恢复先读规则与交接，再核真实状态、产物SHA、实际采用及预算账本；交接摘要可能滞后，不能据旧摘要重复生成。旧文件名、历史报告或另一目录的“最新”文件不能覆盖已登记版本。

**Skill开发仓库根**只维护长期规则和开发任务短交接，课程表仅列课名、绝对根路径、实际布局和课内HANDOFF入口，不重复保存动态课程状态。生产会话只更新本课记录，不再往开发根堆积整课授权、工具调用和交接全文。

每个根记录指定一个汇总写者。改写前保留原字节快照和SHA，建立旧段落到长期规则/课程历史的精确索引；仅存在旧根的有效例外仍须可定位。写入前再次核预期SHA，变化时保存并行新版并合并，不能覆盖别人新增。历史快照不命名AGENTS.md，不要求新会话全文加载；仅按本课/问题读取对应段落。超过摘要预算要分层引用，不能直接截断。

既有课程渐进整理：下次接手且实际需要时再按同样方法处理课内摘要，保留历史、采用和所有原件；不批量搬移课程、不另建第二套_state。根AGENTS目标约150行/12KiB、开发HANDOFF约100行/8KiB，预算不能成为丢掉红线或局部例外的理由。
