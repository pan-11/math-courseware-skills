# 每课四目录与保存地址

适用于整课、独立模块、自动推进、独立审核和课件笔记的文件归位。它只规定保存位置，不改变本次制作范围、采用节点或实际完成条件。以下为新课默认；已有课程沿原布局恢复，不自动迁移。

## 开工先绑定本课根目录

用户会在每课开始时提供地址。给定课程文件夹即作为本课根目录；只有原 PPT 文件、若干分散资料或网络链接时，先判断它们是输入位置，不能擅自把公共父目录当成课程根。根目录不明才问保存地址；同课恢复沿用已登记位置，不重复询问、不另建一课。

读取根目录已有 `AGENTS.md`、`HANDOFF.md` 和文件清单，先明确各目录用途。新课用现有控制器执行：

```text
courseware.py init --project <用户指定的课程根目录绝对路径> --title <课题> --layout four-folders
```

`--project` 始终指课程根，不指 `02_work` 或 `01_source`。手动模式、自动队列、独立审核共用这个根。先用现有运行时定位 Python；不要复制某台机器的解释器或课程绝对路径作为 Skill 默认值。

初始化保留既有根规则、交接和原件；发现未初始化的旧生产目录、已有不明 `02_work` 或两套状态同时存在时先核实，不覆盖、不自动搬迁。原件可以仍在根或外部资料目录；读取后按需原样复制到 `01_source`，记录来源和哈希，原位置保留。不要为了凑成四目录移动用户文件。

## 四类实际位置

```text
<course-root>/
├── AGENTS.md
├── HANDOFF.md
├── 01_source/
├── 02_work/
│   ├── planning/
│   ├── assets/
│   ├── videos/
│   ├── slides/
│   ├── editable/
│   ├── documents/
│   ├── interactive/
│   ├── notes/
│   ├── readable/
│   ├── deliveries/
│   └── _state/
├── 03_final/
│   ├── README.md
│   └── v001/
└── 04_notes/
    ├── README.md
    └── v001/
        └── note-01/
```

四个顶层目录由初始化器建立；子目录按任务需要先声明用途再创建。根只另放规则与交接；生产产物进入四类区域。现存原文件不因整理而删除。独立任务只制作所需内容，不因有四目录就扩成整课；独立笔记不要求伪造上游数据或跑完整课控制器。

| 区域 | 内容与边界 |
|---|---|
| `01_source` | 最初提供的课件、教案、逐字稿、学习单、教材图、参考视频等原样副本。提取文字、页图、抽帧属于加工结果，放工作区。 |
| `02_work` | 教学分析/蓝图、资产和页面版本、剧本/预览/分镜/上传包、生成片段、可画回传、回填版本、文稿/学习单源稿、互动源码、笔记草稿/排版脚本、过程阅读版与全部状态/审核证据。中间资料保留，不能视作可随手清理的缓存。 |
| `03_final` | 沿现有核查要求可交付的 PPT、实际课程视频、三份教师文稿、学习单、黑板贴、互动网页及依赖、使用说明。普通文稿仍按原规则自审交付，不新增逐文件批准。阶段稿与待回填项留工作区并明确状态。 |
| `04_notes` | 按篇成包的封面、顺序内容图、标题正文、所选宣传片段、口播稿、剪辑清单以及真实完成时的视频成片。记录所用教学产品版本、页码和片段依据；待剪辑资料包不算 MP4 成片。 |

生成平台回传的视频、可画回传 PPT 是制作输入，归 `02_work/videos`、`02_work/editable/returned`，不混进原始资料。教学视频成片用于课堂的副本归 `03_final`，为宣传选取的片段归对应笔记。黑板贴源文件归工作区，老师使用的透明素材/PPT/PDF归最终产品。

## 文件操作与记录路径

为了延续现有审批、来源和任务协议，共用 JSON 和专业参考仍使用**逻辑路径**；磁盘文件使用四目录的实际路径。不要直接拿逻辑路径拼根目录来读写文件或生成点击链接。

| 记录/现有参考中的逻辑路径 | 新课磁盘位置 |
|---|---|
| `inputs/...` | `01_source/...` |
| `planning/...`、`assets/...`、`videos/...`、`slides/...` | `02_work/` 下同名目录 |
| `editable/...`、`documents/...`、`interactive/...`、`notes/...`、`readable/...` | `02_work/` 下同名目录 |
| `_state/...` | `02_work/_state/...` |
| `deliveries/...` | `02_work/deliveries/...`，控制器收集暂存 |
| `03_final/...`、`04_notes/...` | 根目录下同名实际位置，不再加 `02_work` |
| `AGENTS.md`、`HANDOFF.md` | 根目录同名文件 |

使用普通文件工具时按本表展开为实际绝对路径；写工作流、来源版本、批准目标、产物引用时统一用逻辑路径。Python 调用 `state.resolve(project, logical_path)` 得到磁盘路径，`state.relative_path(project, disk_path)` 得到记录路径。新课状态实际在 `02_work/_state`；仍以 `_state/math.json` 等记录身份绑定哈希，不因文件归位重新发明采用记录。

既有专业参考的 `videos/V001/v001/asset-kit`、`documents/worksheet-v001` 等均按上表展开。独立审核 packet 里的文件路径也必须经此映射读取，不能因根下没有 `planning` 就判定文件缺失。对用户提供的下载/阅读/文件夹入口一律使用实际位置。

CLI/API省略 `--layout` 仍保留旧初始化行为，用于既有脚本兼容；**本套 Skill 为新课调用 init 时必须显式传 `--layout four-folders`**。已初始化旧课再次 init 不会改变布局。布局按实际状态位置检测，不能手动改一个字段假装完成迁移。

## 交付与版本

1. `02_work` 保留可编辑源、所用输入、完整版本和核查证据。使用 `v001`、`v002` 等版本，不用多个“最终版”互相覆盖；不自动删除旧版。
2. 控制器 `collect` 会收参考图、提示词和部分制作输出，结果只作 `02_work/deliveries` 的暂存。不能把整包直接当作 `03_final`，也不能宣称它已自动收齐视频、学习单、黑板贴或外部文稿。按真实范围另列交付清单。
3. 把已核教学产品及其使用依赖原样复制到 `03_final/vNNN`，把笔记包复制/制作到 `04_notes/vNNN/note-NN`。核来源与副本哈希，保留原制作文件。同一最终包中的 PPT、视频、文稿页码和素材版本须一致。
4. 在各自 `README.md` 标出当前有效版本、文件清单、用法和仍需用户操作的事项；有新版本先核其实际状态再更新入口，修改时间最新不等于已采用。换版影响笔记时核对应篇目，不只改文件名。
5. 最终包包含本次承诺的播放/网页依赖；离线网页及素材引用随包可用。记录实际 PPT 媒体方式与已做的显示/播放检查，不能依赖工作区绝对路径而宣称可直接交给老师使用。
6. 本课阅读报告归 `02_work/readable`，运行与审核证据归 `02_work/_state`；对外说明只链接实际所需文件。Skill 源码、开发测试与通用手册留开发仓库，不复制进每课。

## 已有课程与接力

旧课有根下 `_state/project.json` 就按旧路径继续；不要为了执行新规则打断正在进行的任务。用户另行指定整理某旧课时，先列来源/目标、引用和采用依据，复制验证后再切换入口，旧原件和历史证据保留。本规范没有自动迁移命令，目录变化也不自动更新已有绝对路径绑定的队列/review packet。

根 `HANDOFF.md` 记录本课根目录、实际布局、当前制作/交付/笔记版本、已核事项和最早缺口。恢复先读根规则与交接，再检查实际状态和当前清单。旧文件名、旧报告或另一个目录的“最新”文件不能覆盖本课已登记版本。
