# 共同回复合同

十五个Skill的用户可见回复共用本文件：首次说明、恢复、进度、问题说明、缺项提问、等待回传、修订补交和最终交付都使用同一开头。专业模块只补正文，不另设开头。称呼沿用用户偏好，课件名和版本取当前课程真实状态；非课程执行写实际任务名，不虚构C阶段。

## 唯一开头

```text
〈称呼〉，

课件：〈实际课名〉｜当前步骤：〈阶段／具体子步骤〉｜状态：〈实际状态〉

本步做什么及产出：

1. 〈工作〉 → 〈对应产物；标明计划／进行中／已完成，已存在才给链接〉。
2. 〈仅在确有第二项工作时填写〉。

需要你检查：

1. 〈实际需要检查的内容、当前版本与重点〉。

需要你操作：

1. 〈实际动作、入口和期望回传〉。

下一步：〈具体工作；需要等待时说明实际输入〉。
```

非课程任务将“课件”替换为“任务”。条目数量按真实工作，不凑项。没有检查或操作时，分别写“需要你检查：本步无需检查。”和“需要你操作：本步无需操作。”。编号清单前空一行；不可省略对应位置，也不为填格式制造确认、审核或费用批准节点。

## 内容取值

- **步骤来自真实进度。** 先核本次范围、交接及有效成果。整课使用[共用流程](workflow.md#整课依赖与必需产物)的C1—C8，细分当前动作、V ID或页码；独立模块写“独立回填／文字回填”等，不要求补跑整课。尚未读交接时写“恢复进度／核对已有成果”，产物是进度与缺项清单。
- **只列本步工作。** 讨论情境列候选方案，排逐页稿列逐页稿，不能提前承诺实图或图片PPT。数量须已核实；未生成文件只写计划，不造路径、链接、用户采用或工具记录。不同课程分别说明，不混入别课状态。
- **计划与完成分开。** 产物条目标明计划、进行中或已完成，状态可为待选择、等待回传、待核查、本步已完成。交付已完成步骤时仍标该步完成，下一动作放“下一步”，真正开始后再改当前步骤。素材准备、单片或模块完成都不等于成片或整课完成。
- **等待保持真实身份。** C6等待可画回传时，当前产物是回传PPTX及接收检查；已交去字PPT可标已完成，回填成品属于下一动作。未知回传质量保持待检查。复用同版已提出的请求，不反复催问或把沉默算采用。
- **并行分别说明。** 如“C3视频准备／V001运镜第3步：导演分镜”，分清整课阶段与视频内部编号。固定讲话列首帧及完整提示词，不因格式拆成六步或新增确认。用户已授权提前写C7草稿时，同时保留C6等待和草稿待核状态；正式文稿仍按原依赖执行。
- **问题说明不自行推进。** 用户仅追问进度或讨论问题时，如实写“本课问题说明／方案讨论”，不虚构新的制作阶段。需要检查或操作只列已有流程实际需要的事项，已有同版采用沿用，不新增审批。
- **说明在聊天外层。** 不写进可复制的生图/视频提示词、逐字稿、页面文案或JSON数据。视频交付完整开头之后，再按[视频正文固定模板](../../math-courseware-video-prompts/references/delivery-reply.md#唯一固定模板)写平台/模型、总入口、两张表、各片目录、操作与真实状态；不能用本步产物清单替代正文表格。

## 草稿检查

宿主在发送前检查真实内容；需要机械核对时调用[回复检查器](../scripts/runtime/reply_contract.py)。它只读草稿及明确传入的清单，不写课程状态，不新增采用节点，不拦截所有模型自由输出。

```text
python -X utf8 -B skills/math-courseware-studio/scripts/runtime/reply_contract.py --draft <实际草稿.md> --manifest <实际清单.json>
```

普通进度可不传清单。Python入口为`check(text, *, manifest=None, base_dir=None)`，返回`{ok, issues, warnings}`；独立CLI通过返回0，有缺项返回1。外部清单的相对路径按清单所在目录解析；Python调用时显式传`base_dir`。聊天文件链接始终使用真实绝对路径，有空格或括号时用尖括号包住Markdown目标。

视频清单从本次真实交付目录/manifest核出，不从草稿反推，否则无法发现草稿漏项。仅列本次已存在文件，缺项在正文说明；清单不代替课程真源，也不新增整课状态文件。字段示意如下，路径和数量须换成实际值：

```json
{
  "task_name": "《实际课名》",
  "video_delivery": {
    "entry": "start-here.md",
    "images": [
      {"number": 1, "path": "V001/01-first-frame.png", "display": true},
      {"number": 2, "path": "V001/02-character.png"}
    ],
    "generations": [
      {"label": "第1段·V001·C01", "path": "V001/V001-C01.txt"}
    ],
    "directories": [
      {"video_id": "V001", "path": "V001"}
    ]
  }
}
```

`task_name`须与开头一致；`label`与生成表第一列一致，不规定V ID大小就是课堂顺序。`display: true`用于本次应展示的实际正式板/首帧；同轮已经展示时由宿主核对该事实，不用虚构展示记录。已存在的共用图片只列一次，图号与真实文件名前缀一致；每次生成各有非空独立TXT。部分准备稿仍保留两表，没有已完成项目时对应列表可为空并在正文明确缺项。

检查范围：开头字段/顺序、编号清单/无需、视频正文首项平台/模型（允许未知）、两表固定列名/分隔行/全部行列数/顺序、外部清单中全部编号图和逐次TXT的表内直链、文件名/图号、指定图片展示、总入口、表后各片目录、非空“操作与真实状态：”末段及本地链接存在性。代码块中的示例不算已交付链接；未传视频清单只能查出现的表，不能证明图片或次数齐全。

限制：不解析任意Markdown方言，不验证网络可访问性、图片内容、TXT语义完整性、教学质量、真实采用、平台参数、媒体生成或播放效果；返回warnings如实说明。检查通过只是草稿结构与所提供清单相符，最终由宿主逐项核实并发送，不能据此宣称整课完成。
