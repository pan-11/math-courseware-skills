# 自动推进与独立审核：使用说明

当前源码增加了两个可选入口：math-courseware-autopilot、math-courseware-review。原十二个课件制作模块及独立小红书模块保留，共十五个入口。默认仍使用原有Studio模式；你明确启用后，当前Codex会话按持久任务队列连续制作、独立审核并处理人工待办。关闭聊天后的后台制作、自动批准及付费视频API不在本版能力内。

## 1. 怎么开始

在本项目的Codex聊天中，给出实际课程目录并发送：

> 读取 skills/math-courseware-studio/SKILL.md 和 skills/math-courseware-autopilot/SKILL.md。为 projects/实际课程目录 启用自动推进＋独立审核。先核对已有文件、当前进度和已采用版本，在我授权的范围内连续执行；保留现有人工采用节点，遇到外部操作及时给出完整操作包和回传要求。

AI负责读取规则、建立具体队列和填写状态，不需要你写JSON或手动敲控制器命令。新课照常先提供原课件或明确教学要求；没有原课时做需求分析，不编造原页数和原视频。

在其他电脑/另一个项目中使用时，须有包含两个新入口的当前完整源码和所需运行环境。旧发行包、旧安装副本不会自动更新；没有全局安装也可以在当前工作区直接按上述文件入口使用。

## 2. 两种制作模式共存

| 项目 | 原有模式（默认） | 自动推进＋独立审核 |
|---|---|---|
| 谁衔接步骤 | 当前AI按Studio规则衔接，你可逐段指导 | 持久队列选择下一项已具备前置条件的任务 |
| 谁做产物 | 原有专业Skill | 同一批专业Skill |
| 如何检查 | 原模块自检；按需独立审核 | 原模块自检后再交新的独立审阅者 |
| 发现问题 | 按你的要求或当前自检修正 | 一般本地任务有限修正并重审；外部/付费任务不自动重试 |
| 人工节点 | 沿现行规则 | 同样保留；采用、外部操作与回传单独登记 |
| 中断恢复 | AGENTS、HANDOFF与实际产物 | 加上保存的队列、任务claim和审核包，先核原任务再续作 |

同一课程共用实际文件、版本和用户确认。自动模式不会把审核报告变成你的批准，切换模式也不会重建课程。

## 3. 自动模式怎样把整课连起来

每个制作任务的循环是：**核前置与授权 → 原Skill制作实际产物 → 原模块自检及登记 → 独立审核 → 必要的有限修正 → 满足采用条件后继续。** 审核报告逐项给出“通过／需修改／未验证”，没有实际看听的内容不能算通过。

| 阶段 | 主要产物 | 需要你接手的地方 |
|---|---|---|
| C1 原课/需求分析 | 质量与教学流程分析、数学和来源清单、原视频读取情况 | 关键原始资料缺失时补材料；分析不另加采用关口 |
| C2 整课蓝图 | 完整教学蓝图、共同故事与数学核心、全部视频节点和课时/页数预算 | 审阅具体整课方案；只选故事不等于采用蓝图 |
| C3 视频准备 | 剧本、逐字声音、适用预览/实际资产、导演/正式板/固定风格、完整生成词与操作包 | 按现有分组审阅；在实际视频平台操作并回传媒体。固定讲话保持简路 |
| C4 逐页内容 | 逐页教学内容、准确文字、视频页和课堂接话映射 | 按现行规则采用具体逐页内容 |
| C5 页面图片 | 带字试样、完整全套页面图 | 采用试样/全套图片；首次线路及新增费用授权按实际情况处理 |
| C6 可编辑课件 | A/B对应交接包、真实回传PPTX、整套文字回填、视频回填 | 明确A/B；可画拆层并回传真实文件；WPS动画/实际播放按原要求操作 |
| C7 配套资料 | 教学设计、逐字稿、说课稿、学生学习单四份Word及电子黑板贴 | PPT完成依据不明确时确认版本；内容未完成时不能默认交正式稿 |
| C8 汇合交付 | 当前PPT、真实影片、四Word、黑板贴、实际交付清单和检查记录 | 实际WPS投屏、视频音画与课堂衔接核查；队列完成不能代替整课验收 |

真实成片制作可在准备材料采用后与允许的PPT工作并行；正式配套仍核PPT完成情况。等待某个人工任务时，其他已经满足前置且在授权范围内的工作可以继续；不会为了继续而绕过视频准备或蓝图采用。

HTML课堂互动仍按具体课程约定，在蓝图中规划并纳入最终实际检查。小红书Skill仍是另外调用的后续分支，本次启用自动课件模式不默认制作或发布小红书内容。

## 4. 只想审核，不开启自动模式

> 读取 skills/math-courseware-review/SKILL.md。独立审核［产物路径］，以［原始资料/已采用蓝图路径］为依据。请让新的只读审阅者检查，给出具体位置、问题、修改建议和未验证项；不修改文件，不代替我采用，也不启动自动制作。

AI会准备绑定版本的审核包，实际派发独立审阅者，再保存其真实报告。审核者缺少必要工具或证据时会明确未验证。没有独立代理能力的环境会停在等待，不用同一制作者的自评冒充独立审核。

## 5. 暂停、恢复和切换

| 你可以这样说 | 实际行为 |
|---|---|
| “暂停当前课程自动推进” | 停止派发下一项，保留已派发任务和外部在制记录；不宣称取消了平台任务 |
| “恢复当前课程自动推进，先核已有任务和文件” | 恢复队列；已经在做的任务先查询、等待或回收结果，不盲目重复派发 |
| “切回原有制作模式，保留现有进度” | 关闭自动派发，原Studio继续可用；队列和文件保留 |
| “重新启用自动模式，从当前实际版本继续” | 核来源与队列，必要时按真实指令协调当前范围，再处理失效项 |
| “只重审这一版，不继续制作” | 新建独立审核包，保留旧审核；不扩展为整课制作 |

上游文件改动、选用新版蓝图或明确否决后，旧审核不能继续沿用。AI会标明受影响的任务，按实际版本重做或重审。遇到外部提交结果未知，先找实际任务/文件；本版不会自动再次提交。

## 6. 你会看到哪些文件

课程原有planning、videos、slides、editable、documents等目录保持。新增管理记录集中在课程的`_state/automation/`：

- `active.json`：当前队列指针。
- `runs/<run-id>/run.json`：模式、任务、等待、尝试和当前进度；同目录`revision-*.json`保留变化记录。
- `reviews/<review-id>/packet.json`：本次审核的实际文件、SHA256、依据和检查项。
- `reviews/<review-id>/result.json`：真实独立审核报告与汇总结论；不作为用户采用。
- `HANDOFF.md`：仍由AI维护可读交接，不要求你阅读内部JSON才能使用。

控制器没有直接执行任意shell命令或自行生产内容；它负责可靠登记与派发，由当前Codex会话调用现有Skill和工具。连续工作的前提是会话仍在运行、需要的工具可用、当前范围与采用条件满足。

## 7. 当前边界

本版新增可选队列与独立审核，保留原来的人工采用节点。最终交付仍需实际核对当前文稿、所有视频和黑板贴，不能只依赖旧collect/complete检查；尚未把已知最终文稿版本绑定/自动收集缺口宣称修复。文件哈希与身份信息用于版本和来源追溯，不是对同磁盘权限任意篡改的安全隔离。

两个入口及执行协议：[自动推进](../skills/math-courseware-autopilot/SKILL.md)、[队列协议](../skills/math-courseware-autopilot/references/queue-contract.md)、[独立审核](../skills/math-courseware-review/SKILL.md)、[审核协议](../skills/math-courseware-review/references/review-contract.md)。

## 8. 启动集中设置与补充

首次启用时，AI先复用当前课已知选择，再一次集中补齐：生图线路和授权用途/范围/费用；视频平台/模型/声音；可编辑A/B及从整套交接或已有回传开始。未知项不会挡住分析、蓝图和无关工作；不沿用其他课程偏好。已明确的选择切换模式、恢复聊天后继续生效，不重复问。

AI把实际值和原话存入run版本；CLI仍是非交互。后续明确改选或补充使用run-configure部分更新，run-status显示当前偏好、缺项和冲突。生图可按本run授权指定用途的首次制作，或收窄到具体目标版本；付费生成与返工须在真实授权中明确包含。已付费旧任务切换路线后仍能查询下载，未知提交不自动重试。设置不替代任何已有用户采用门槛。

## 9. 图片数量上限

新自动run默认最多60张，封面、资产、视频预览/导演板、页面、测试、去字与返工共同累计；一张25格拼图算1张，四张独立封面算4张。API会在提交前检查整批：剩2张而本批需4张时，一张也不提交；并发预占防止超支，失败和未知尝试也保留占用。重复查询下载不再计数。

内置生图是软上限：AI先按任务声明张数核余量，真实成功结果登记后计数。同结果重复登记不再计数，已经生成的超额图仍保存并显示超额，后续生成暂停。脚本无法阻止未登记的直接工具调用，也无法完整计数失败或未知的内置调用；没有内置预占凭据操作。

达到上限后，需要你实际授权新的总上限，AI用run-configure记录原话并保留旧账；只说恢复或切回手动不会清零。旧run没有预算时先明确设置上限，状态显示从何时记账、此前用量未知，不扫描估算旧用量。已提交图片仍可查询、下载和登记；数量设置本身不等于付费授权。无自动run的原手动模式保持原样。

旧队列的待办若还缺未来生图张数，AI可按已确定方案用run-configure补充数量及依据，沿原任务ID和依赖继续。只允许从未派发、从未尝试且没有已有张数声明的任务；不猜历史生成量，不清零、不重建队列，也不借补数量改动原任务内容。

补张数依据由AI按实际制作计划记录，不冒称你作了新的批准；扩大总上限仍需要你的实际授权。补张数、偏好和总额可以一次写入，任一项无效时整次都不保存。

## 10. 人工决定与审核结论的学习记录

在本课有自动run时，每次真实采用、否决、操作回传或启动设置都会记录实际版本和你的原话。AI先保存你看到的同版独立审核，再登记你的决定；你没说原因就留空，不追问、不猜原因。没有审核、审核未验证、只采用一部分或版本/整组范围不对应，也照实留记录，但不计入一致率。后来的审核不会倒填成你作决定前已有的意见。

run-status按阶段显示一致、不一致、未配对及可比样本量；同时单列“审核通过却被你打回（误放）”和“审核要求修改但你仍采用”。一致率是可比样本中的一致比例；没有可比样本显示“暂无可比样本”，不显示100%。设置选择与普通操作不硬算对错，默认60张和AI补未来张数不冒称你作了选择。

记录保存在本次run目录的calibration.jsonl；四目录课实际位于02_work/_state/automation/runs下。重复恢复不会重复计数，你后来明确改口则保留前后两次；两种入口登记同一采用会关联原事件。写入中断时先显示缺口，后续修改/恢复命令补写原快照；只看状态不改文件。部分答复或否决留在等待，不能用“完成”结束该节点。

同一次答复后来补审核报告、节点或理由注释，不增加票数，也不能把晚到报告配回原答复。发生顺序使用持久序号，系统时钟调整不会让旧采用链接重新生效。日志半行中断时，状态会明确标为不完整；能核对原快照的尾部只追加缺失字节，未知损坏会明确报告并停止写恢复，保留原始记录。

这项记录用于观察审核是否可靠，不赋予审核者采用权、图片扩额权或自动批准权。原有人工门槛不变；没有run的原手动课不新增这些文件，同一run切回手动仍保留其真实决定记录。

你先否决某稿后，原人工节点仍能收录同一版的实际退回复述，页面会说明上游已阻塞；这不代表又要你采用，也不会把否决记成完成。中间处理了其他页或视频，再重放同一批准记录不会多算一次；组内某项被否决后你真正重新采用，才保留新的决定。
