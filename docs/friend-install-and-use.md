## 二、这套Skill是什么，整套课件怎么用

这是一套让AI按固定流程协助制作课件的工作规则和执行脚本，整套流程按小学数学设计。一般从总入口开始，AI根据已有进度调用专业模块。

| Skill名称 | 负责的工作 |
|---|---|
| `math-courseware-studio` | 整课总入口，安排流程、确认、版本与交付 |
| `math-courseware-analyze` | 可见原课质量分析、优点与优化、逐页流程、视频清单及数学核查 |
| `math-courseware-plan` | 整课教学蓝图、教学情境、共同故事、风格及共享资产 |
| `math-courseware-pages` | 逐页文案、页面提示词与实际页面图 |
| `math-courseware-editable` | 可画交接、已有PPT文字校正或回填 |
| `math-courseware-documents` | 教师课堂逐字稿、说课稿、教学设计 |
| `math-courseware-video` | 视频总入口，组织两条视频路线 |
| `math-courseware-video-writer` | 剧本、完整台词、25格剧情预览 |
| `math-courseware-video-assets` | 角色/场景/道具实图、讲话首帧及固定风格 |
| `math-courseware-video-director` | 节拍、调度、运镜及静态/动态分镜双表 |
| `math-courseware-video-storyboard` | 正式黑白故事板实图及检查 |
| `math-courseware-video-prompts` | 完整视频词、上传映射及使用说明 |

准备原课件、教材页或明确的课题/年级/目标，再提供页数要求、想要的情境和参考画风；没有完整故事也可以开始。具体教材题目和数据应有可靠来源。

整课依次推进：

1. **展示原课分析。** 先说明原课制作得怎样、哪些地方值得借鉴、哪里需要优化；报告实际总页数、隐藏页及读取范围，列完整教学流程和每页作用。另列视频去重片数与播放位置数、原页码、具体内容、教学作用和前后衔接；没有实际看听的视频说明依据与未知项。只有PDF不能断言原PPT没有视频，没有原课件时做需求分析。
2. **采用整课蓝图与共同故事/数学。** 一起确定目标、活动、评价、教学流程、课时、页数预算、全部视频的数量和作用，以及故事和不可改数学。只选定一个故事不代表整课方案已采用。
3. **完成全部计划视频的创作与准备。** 从头制作整课时视频为必做；按后面的两路流程逐一准备所有计划视频。视频第二步可同时完成共享风格和角色、场景资产。只完成第一段视频不能直接跳到整课逐页制作。
4. **制作PPT逐页文案和实际图片。** 视频页计入总页数；先完成视频方案与流程，再推进逐页制作。实际视频成片可在准备完成后与PPT并行制作。
5. **制作可编辑PPT和三类文稿。** 可画A为带字拆层后校正，B为去字拆层后回填；进入制作前明确选择。三文稿可以在图片课件锁定后开始。
6. **回填实际视频并检查播放。** 检查课件、视频及文稿一致。动画由使用者在WPS/PPT手动设置；尚无成片时属于视频待回填阶段稿。

整课中进入视频或可编辑模块，仍保留全课目标和其他待办。只做已有PPT回填、某段视频或某份文稿时，直接检查本模块真实输入，不要求从头重做。AI维护范围、产物和采用记录；旧项目缺少新索引时先依据真实历史核对接入，保留成果，不要求你手写JSON。

## 三、单独使用可编辑PPT：接收可画无字版并回填文字

### 你需要先准备什么

你的起点是：**已在可画完成去字与拆层，导出一份PPTX，页面中的图片元素可以分别选中、移动或缩放。** AI接下来负责文字回填和检查。

| 材料 | 要求与作用 |
|---|---|
| 无文字、已拆层的PPTX | 必需，保留完整页数与顺序；交PPTX文件，PDF/截图不能替代待编辑文件 |
| 每页正确文字 | 必需的内容依据，可提供逐页定稿文字，或提供可读取的带字原版后核对提取结果；包含标题、题目、算式、答案和标签 |
| 带字参考PPT/PDF/图片 | 建议同时提供，用于恢复文字位置、字体、字号、颜色和换行；按原页序对应 |
| 字体及特殊要求 | 例如默认楷体、哪些算式或答案要分开用于动画；有特殊字体需本机实际可用 |

无字页面本身不能说明原来写了什么。只有带字参考图时，AI先提取并核对文字，遇到模糊字符、数学符号或来源冲突集中确认；你已明确指定的定稿文字直接沿用。没有带字版式参考但有完整文字时，AI可以根据页面实际留白排版，并说明版式为本次安排。

### 完整执行顺序

1. **接收原件并检查。** 保存上传原件的副本和哈希；查看实际页数、比例、顺序及对象。核实导出的图片元素确实仍可独立选择，记录未拆开区域、残留文字或异常分组。
2. **对应逐页文字。** 把每页文字与真实PPT页码对应。以你指定的定稿为准，带字参考负责视觉定位；提取出来但尚未核准的内容明确标注。
3. **建立回填记录。** AI自动建立必要项目记录、页面与文字单元、对象清单、字体和坐标计划。若这是外部制作的PPT，从真实输入建立最少记录即可，不要求先重做课程故事、页面生图或视频。已有记录直接复用；真实内容确认和整套制作授权分别记录。
4. **直接整套回填。** 本次明确采用B路线的回填阶段，已完成的去字和可画拆层不重复。文字来源确定后在工作副本中完成全部页面，不额外设置单页试样或坐标审批。标题、题干、答案、步骤及数学标签分别建立原生文字对象；需要逐项动画的算式可分片，拼回后仍须与原文完全一致。
5. **整套逐页检查。** 回读文字，核对漏字、错字、数学符号、字体、字号、位置、换行和遮挡；检查图片、分组、裁切与叠放关系。保留原图层，不以整页截图替换。仍未独立的必要数学对象单列，不能把文字回填完成当成所有图形都已拆好。
6. **交付并实际复核。** 交付新版PPTX、逐页预览或PDF及检查清单，说明未解决项。你在自己的WPS/PPT打开检查，按需设置动画；结构检查、视觉检查和实际软件显示分别记录。

可画导入/拆层/导出由你操作；AI处理你上传的实际PPTX及文字。回填本身不依赖重新调用生图服务或可画在线插件。原图中仍粘在一起的细节按实际对象记录，不承诺自动拆成任意粒度。

20260918测试曾出现OfficeCLI回填异常，20260919修改前的原60项回归均通过，未复现该异常。后续制作仍以朋友机器上的实际结果为准，写入失败时保留原件和错误记录，不能交一个仅改名或只有预览的文件并宣称回填成功。

```text
交付新PPTX、预览或PDF、逐页检查结果及未解决对象清单。这次只做PPT文字回填，不额外制作新故事、视频、课件图片或教学文稿。
```

## 四、单独使用视频模块

统一从`math-courseware-video`开始，不必分别安装或手动切换五个专业模块。可以只有“游乐园”“小动物商店”等粗情境，再说明学生年龄、想让他们看到什么、预计时长及已有素材；已有台词、角色图和不可改条件一并给出。没有故事或角色图时由AI补齐。

### 路线一：一个角色固定讲话

适用：全程同一个角色说话，固定机位，没有运镜和切镜。自然口型、表情与轻微手势仍属于这一路线。

顺序是：

1. **完整台词与画面安排。** 明确角色、场景、站位、说什么、说话语气及结束状态。
2. **生成实际彩色单首帧。** 复用已有角色/场景参考，缺失部分由AI制作；脸和嘴要清楚，构图符合你的要求。三视图是形象参考，实际首帧是完整单画面。
3. **审阅人物、构图与台词。** 修改有问题的部分，同版已有确认继续沿用。
4. **整理数字人操作材料。** 交付首帧、完整台词及必要参考，核实当前即梦数字人入口的输入方法。入口支持台词时使用完整正文，需要音频时使用实际配音文件，不能把文字文件当作已生成音频。
5. **实际生成并检查。** 在平台按核实后的操作制作，再检查口型、声音、台词完整性和画面。默认无BGM、无字幕，保留角色说话和适用音效。

这一路线不安排25格剧情预览、导演多镜头双表或黑白故事板。若要求“先环绕场景，再切角色讲话”，整段应走下一条运镜切镜路线。

启动语：

```text
读取本项目安装说明，定位并使用math-courseware-video。
我要做一个单角色讲话视频：【角色】在【场景】中介绍【内容】，面向【学生年龄】，预计【时长】。
全程固定机位、无运镜、无切镜。请写完整台词，生成实际彩色首帧，整理即梦数字人使用材料。若我已有台词或角色图，优先沿用。
本次先完成图片与台词素材，放在同一个普通文件夹，不默认生成付费视频。
```

### 路线二：有运镜、切镜或场景变化

固定六步，图片资产位于第一步和导演步骤之间：

| 步骤 | 谁负责 | 做什么、拿到什么 | 主要检查 |
|---|---|---|---|
| 1. 剧本＋25格剧情预览 | video-writer | 从粗情境写可见事件、完整台词，实际生成5×5关键画面预览；根据反馈改剧本与相关预览 | 想看的事件是否真的出现，开头有无明确看点，动作与结尾是否连贯 |
| 2. 图片资产 | video-assets | 复用或生成角色正侧背三视图、场景多角度和必要道具，整理风格初稿 | 同一个角色/地点是否一致，数量与结构是否正确，后续镜头所需视角是否齐备 |
| 3. 导演分镜 | video-director | 先安排节拍与空间，再输出规范的导演文档及静态/动态双表 | 运镜有没有观看目标，起止与揭示内容是否清楚，动作/对白是否容纳得下 |
| 4. 正式黑白故事板 | video-storyboard | 根据正式静态分镜和实际参考图生图，按镜号核对并修改 | 板格、构图、人物位置、动作状态和镜号是否与导演一致 |
| 5. 固定风格文字 | video-assets | 从本片实际采用的彩色角色/场景图提炼固定风格描述，各段统一复用 | 媒介、材质、配色和人物比例是否符合本片实图；黑白板不决定成片颜色 |
| 6. 完整视频提示词 | video-prompts | 按自然动作和当前平台能力划分片段，输出每段可单独复制的完整词与上传文件映射 | 台词完整、镜号对应、各段风格一致、引用是真实且正确的文件 |

25格用来看剧情，不等于每格一秒，也不等于25个正式镜头。第四步的黑白故事板控制正式镜头构图，格数随镜头需要确定，不固定为13格。第一步预览可以使用已有或临时形象，不必先做齐第二步的全部正式设定图。

导演文档中，**节拍**说明剧情、信息或情绪怎样变化；**静态分镜**说明每镜看见什么、如何构图；**动态分镜／视频词基础表**说明怎么动、说什么、持续多久及有什么音效。第六步把动态表内容与参考图、风格等组装成平台使用的完整提示词。

重点看两组创作成果：**剧本＋25格预览**、**导演方案＋正式黑白故事板**。人物和场景效果可以结合这些成果审阅，同版已有确认沿用。平台或配音尚未确定，不阻断已明确的图片资产制作；工具不可用或未返回时，如实列出实际缺图与下一步。

每段最终视频提示词包含五部分：

1. **声音要求：** 不要出现BGM，不要出现字幕，保留剧本对白和环境／动作音效。
2. **真实参考映射：** 逐张说明角色、场景、道具和故事板的用途。场景图默认用于环境设定，不自动锁成首帧或要求逐帧照搬；明确制作的实际首帧另行说明。
3. **统一风格原文：** 每段使用同一份已冻结的文字描述。
4. **故事板范围与状态接续：** 这次生成哪几个镜号，从什么状态开始、在哪里结束，怎样接上一段。
5. **动态镜头全文：** 完整写出时长、构图、景别、机位、运镜、台词、动作、节奏和音效。

六步结束后，实际素材与文字放在一个普通文件夹，提供一个`start-here.md`入口，说明每段该上传哪些真实文件、复制哪段词、按什么顺序制作。实际图、台词和提示词集中保存，不自动压缩；只有提示词而缺图片时不能称素材已经齐备。

**接着制作成片：** 核实当前平台的参考输入、标签和时长限制 → 按上传映射生成有代表性的片段 → 检查人物、动作、声音和约定事实 → 修正对应环节 → 制作其余片段 → 需要时按顺序拼接 → 看完整视频并听声音。已有工具和费用授权允许AI操作时按实际能力执行，否则由你在平台操作并回传结果。素材准备完整、平台可提交、实际成片通过是不同状态；本套没有内置视频生成API。

启动语：

```text
读取本项目安装说明，定位并使用math-courseware-video。
我要做一个面向【学生年龄】的情景视频，大致情境是【填写】，预计【时长】，需要运镜和切换镜头。我目前没有完整故事，请从粗情境开始。
我希望学生实际看到：【填写具体活动或想要的观看体验】。
已有角色、台词、场景图和不可改变的条件：【填写；没有就说明没有】。

按六步推进：剧本＋实际25格剧情预览→角色/场景/道具图片资产→导演分镜→正式黑白故事板→从采用彩色图提炼固定风格→完整视频提示词。
先完成剧本和实际预览供我审阅，再按已确认进度继续。图片由你用当前真实可用且已选定的生图线路生成并查看，不能只交提示词代替图片。
最终把实际素材、完整台词、分镜、逐段视频词和上传用法放在同一个普通文件夹。本次先完成这些素材，实际视频生成按我后续指定的平台和授权执行。
```

## 五、以后怎样继续

在同一工作文件夹里，提供原课程或视频项目路径，发送：

```text
读取本项目安装说明，继续【已有课件或视频项目的实际路径】。
先读该项目AGENTS.md和HANDOFF.md，再核对真实文件与已确认版本。

```

提示词中的制作例句是后续主动发起任务时使用。安装成功表示工具文件与已检查环境的状态，真实生图、可画回传、视频效果和WPS显示仍以当次实际成果为准。
